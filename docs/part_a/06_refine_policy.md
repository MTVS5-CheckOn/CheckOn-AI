# [체크온] 핑퐁 다듬기 정책서 v0 — `/v1/drafts/{id}/refine` 구현 규칙

> **지위:** member-A 단독 정의 가능(🟡). 단 §5 소모 시점은 백엔드 BE-4 합의 필요 — `[제안]` 표기.
> **한 줄 원칙:** 강사는 자유 문장으로 무한히 다듬을 수 있지만(월 할당 내), **강사 지시가 게이트를 이기지 못한다.**

---

## 1. 동작 개요 (계약 §3.4 재확인)

- `scope: whole | block`, 자유 지시문 `instruction`, 버튼은 `preset`으로 흡수.
- 202 → GET 시 `revision_no` 증가, `revisions[]` 턴 이력, 롤백 `{"revert_to": n}`(미소모).
- 매 턴 결과도 게이트 전체(Evidence → SourceGrounding → ToneSafety) 재통과.
- 1턴 = 상담 초안 할당 1 소모. 세션 턴 상한 없음 — 월 할당이 자연 상한.

## 2. preset 3종 정의 (프롬프트 파라미터)

| preset | 톤 | 구성 | 길이 | 구현 |
| --- | --- | --- | --- | --- |
| `softer` | 완충 표현 +1단계(buffer_lexicon 치환 강화), 단정 서술 → 관찰 서술 | 유지 | 유지 | 라벨 `sensitivity=anxious` 규칙과 동일 프로파일 재사용 |
| `conclusion_first` | 유지 | 핵심 결론(제안 블록)을 첫 문단으로, fact 블록이 뒤에서 뒷받침 | 유지 | 블록 재배열 + 연결 문장만 재생성(전체 재생성 아님) |
| `shorter` | 유지 | 유지 | 블록당 최대 2문장·전체 60% 이하 | evidence 인용은 축약해도 **삭제 금지**(게이트 통과 유지) |

preset과 instruction 동시 입력 시: preset을 기본 파라미터로 깔고 instruction을 우선 적용. 충돌(예: preset=shorter + "더 자세히")은 instruction 승(최후 지시 우선).

## 3. 지시문 해석 규칙 — 허용/검증/차단 3분류

| 분류 | 예시 지시 | 처리 |
| --- | --- | --- |
| **A. 스타일** (허용 — 즉시 반영) | "더 짧게", "존댓말 강도 낮춰", "다음 상담 일정 제안 문장 추가" | 프롬프트에 지시 그대로 조립. 단 결과는 게이트 재통과 |
| **B. 사실 조작** (근거 검증) | "정답률도 언급해줘", "6월 모의고사 얘기 넣어줘" | 스냅숏·evidence에 해당 데이터가 **있으면** 반영, 없으면 차단(`evidence_missing`) — "있는 것만 말한다" |
| **C. 정책 위반** (차단 — LLM 호출 전 정적 검사) | "반 평균이랑 비교해서 써줘"(학부모向), "옆 반 ○○이보다 잘한다고", "실명으로 써줘" | 차단 + `blocked_reason` 반환. **LLM 호출 자체를 안 함** |

## 4. `blocked_reason` enum (에러·상태 코드 사전과 공유)

| 코드 | 뜻 | 검출 시점 | 백엔드 표시 문구 제안 |
| --- | --- | --- | --- |
| `evidence_missing` | 지시한 수치·사실의 근거 부재 | 생성 후 SourceGrounding | "요청하신 내용은 기록에서 확인되지 않아 반영하지 못했어요" |
| `comparison_exposure` | 학부모向에 teacher_only 지표(반 평균·석차) 노출 지시 | **사전 정적 검사** | "반 평균·석차는 학부모 문서에 포함할 수 없어요(내부 지표)" |
| `tone_violation` | 낙인·단정 표현 강제("게으르다고 써줘") | 생성 후 ToneSafety | "해당 표현은 안전 기준에 걸려 완곡한 표현으로 제안했어요" |
| `pii_exposure` | 실명·연락처 삽입 지시 | 사전 정적 검사 | "개인정보는 초안에 넣을 수 없어요" |
| `out_of_scope` | 초안과 무관한 요청(잡담·타 학생) | 사전 정적 검사 | "이 초안의 다듬기와 무관한 요청이에요" |

부분 차단 규칙: 지시가 복합("짧게 + 반 평균 비교")이면 **가능한 부분만 반영**하고 차단분 사유를 함께 반환 — 턴 전체를 버리지 않는다.

## 5. 할당 소모 시점 — (7/15 확정) 집행은 전부 백엔드

> **회의 확정:** 카운트·차단·잔여 표시 전부 백엔드 Billing. **AI는 refine을 쿼터 무관하게 처리**하고 쿼터 정보를 반환하지 않는다. 아래 표는 백엔드 집행 설계 참고용(정적 차단 턴의 미소모 등 A의 원안 논리 유지 권장).

| 케이스 | 소모 | 근거 |
| --- | --- | --- |
| 정상 반영 턴 | 1 | 기본 |
| 생성 후 게이트 차단(B·`tone_violation`) | 1 | LLM 원가 발생 — 소모하되 사유를 명확히 |
| **사전 정적 검사 차단**(C 분류) | **0** | LLM 미호출 — 원가 0, 강사 억울함 방지 |
| 롤백 `revert_to` | 0 | 저장된 리비전 복원만 |
| 부분 반영 턴 | 1 | 호출 1회 |

카운트 주체는 백엔드 Billing(402/429 차단도 백엔드). AI는 응답 `meta.quota`에 잔여 동봉 + `usage_daily` 미터링만.

## 6. 문체 프로필(STYLE_PROFILE) 축적

- **재료 2종:** ① refine `instruction` 원문(의도 신호) ② 강사 직접 수정 diff(`/confirmations` kind=draft_edit).
- **축적 방식:** 즉시 반영 아님 — 주간 배치로 반복 패턴만 추출해 `features`에 병합(예: "매번 '~같아요'로 완화" ×5회 → 선호 어말 등록). 1회성 지시는 프로필에 안 들어감.
- **적용:** 이후 초안 생성 시 시스템 프롬프트의 스타일 힌트로만 — 게이트·라벨 규칙보다 항상 하위.
- **프라이버시:** instruction도 redaction 통과 후 저장(강사가 지시문에 실명을 쓸 수 있음).

## 7. DRAFT_REVISION 저장 규칙 (ERD v2 확정분)

- 턴마다 1행: `scope · block_seq · instruction · preset · result_blocks(스냅숏 — 롤백용) · gates_passed · blocked_reason · llm_call_id`.
- `result_blocks`는 전체 블록 스냅숏(차분 아님) — 롤백을 단순 복원으로.
- 차단 턴(소모 0)도 행은 남긴다(`gates_passed=false`, result_blocks=null) — 감사·게이트 공격 케이스 수집(평가 계획서 #9의 재료).

## 8. 테스트 케이스 (골든셋 시드)

1. "더 짧게" → 60% 이하 + evidence 유지 ✅
2. "정답률 95%라고 써줘"(실제 62%) → `evidence_missing` + 원문 유지
3. "반 평균이랑 비교" (학부모向) → 사전 차단, 할당 미소모
4. shorter preset + "더 자세히" instruction → instruction 승
5. 10턴 연속 후 `revert_to: 3` → 3턴 시점 복원, 소모 없음
6. 복합 지시 부분 차단 → 반영분 + 사유 동시 반환
