## 3. `chart_analysis` 블록 스키마

```json
{
  "seq": 3,
  "block_type": "chart_analysis",
  "chart_ref": "improvement_trend",
  "content": "5월 셋째 주 보강 이후 문학 정답률이 58%에서 71%로 올랐습니다...",
  "evidence": [{ "source_table": "feature_week", "record_id": "fw_w21" }],
  "numbers_used": [58, 71]
}
```

- `numbers_used`: 문장 속 등장 수치 목록 — SourceGrounding이 차트 확정 수치와 **전수 대조**(하나라도 불일치 → 블록 재생성, ≤3회 후 비움).
- 블록 순서(리포트 본문 구성): 인사 → 학습 요약(fact) → 차트 해설 ①②③ → 제안 → 맺음. 각 chart_analysis는 해당 차트 바로 아래 배치.

## 4. 노출 3층 매트릭스 — 구현 기준표

| 데이터 항목 | 학생 화면 | 학부모 리포트 | 강사 화면 |
| --- | --- | --- | --- |
| 본인 정답률·추이 | ✅ | ✅ | ✅ |
| 영역별 약점 | ✅ (성장 프레임) | ✅ | ✅ |
| 전국 백분위 | ❌ **비교 일절 비노출** | ✅ (`audience: guardian`) | ✅ |
| 반 평균 | ❌ | ❌ (`audience: teacher_only`) | ✅ 내부 관리 도구 |
| 반 석차 | ❌ | ❌ | ✅ |
| 위험 신호·경보 | ❌ (낙인 방지) | ❌ (강사가 상담으로 전달) | ✅ |

**teacher_only 구조적 제외 — 구현 방식:** 컨텍스트 조립기(composition의 assembler)가 draft `kind`와 수신 대상으로 **audience 필터를 프롬프트 조립 전에 적용** — `audience: teacher_only` 항목은 LLM 입력에 아예 미포함(프롬프트에 없으면 유출 불가능). 게이트로 사후 검출하는 방어가 아니라 입력 차단이 1차. ToneSafety의 비교 표현 검출은 2차 방어.

## 5. 하위 백분위 완곡 규칙 (라벨 연동 — 매핑표 #4와 공유)

- **수치는 사실대로** — 백분위 숫자를 바꾸거나 숨기지 않는다(Evidence-first).
- **문장은 성장 추이 중심** — "하위 32%" 단독 서술 금지, 반드시 개선 추이·다음 계획과 병기.
- `sensitivity=anxious`: 완곡 +1단계(buffer_lexicon), 백분위 해설을 제안 블록 뒤로 후치.
- `comm=data`: 수치 표 중심 + 짧은 해설 / `comm=narrative`: 서사 중심 + 수치는 근거로.
