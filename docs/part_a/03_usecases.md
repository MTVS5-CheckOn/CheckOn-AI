# [체크온] member-A 유스케이스 v3 — 시나리오 17종 (박진희)

> **v2 → v3 변경:** ① C1의 "톤 조절 버튼" 서술을 **채팅형 다듬기(/refine)**로 교체하고 전용 시나리오 **C8 신규** ② **C9 신규** — 월별·단건 리포트(chart_analysis·노출 3층) ③ I4 태깅을 **수능 6영역 enum + item_format**(Open-11 확정 7/15 · v1=mcq만)으로 개정 ④ 공통 검증 축에 ⑦ 사용량 미터링 추가 ⑤ 테스트 매핑을 평가 계획서 v0(golden/ 구성)와 연결.

**공통 검증 축(모든 시나리오에 적용):**
① 신호·라벨·게이트 판정은 결정론 코드가 확정 — LLM 접점은 7곳(초안·계획·매핑 조사·문장화·분류·태깅·라벨 제안, 다듬기는 초안 접점의 반복)이지만 **어느 곳에서도 LLM이 수치·판정을 확정하지 않는다** ② evidence 없는 산출물은 존재하지 않는다 ③ 승인·발송·확정은 전부 `ai/` 밖(HITL) — 에이전트도 예외 없음 ④ 실명·연락처는 AI 경계를 넘지 않는다(alias + masking, 에이전트 도구 포함) ⑤ 모든 실행은 RunMetadata + (에이전트는) AGENT_STEP으로 재현·감사 가능 ⑥ 모든 루프에 상한이 있다(블록 3회·조사 5회·학생 큐 유한 — refine은 턴 상한 대신 **월 할당이 자연 상한**) ⑦ **(v3 신규)** 인터랙티브 생성(초안·refine 턴·문항·단건 리포트)은 전부 할당 미터링 대상 — 차단(429)은 백엔드 Billing, AI는 `meta.quota` 동봉과 `usage_daily` 기록만. 감지·분류·태깅·일괄 작업은 할당과 무관.

## A. detection — 위험신호 감지 (결정론 · LLM 0 · v1 유지)

### 시나리오 D1 — 해피패스: 숨은 위기 신호 생성

**상황.** 김서현 강사의 고1 A반 서연이는 3주째 정답률 81%로 멀쩡하다. 그런데 비문학 지문 하나를 붙잡는 시간이 조용히 늘고 있다. 새벽 2시, 야간 배치가 돈다.

1. 백엔드가 주간 학습 스냅숏을 REST로 넘긴다(alias만, snapshot_hash 포함).
2. `ai_run` 기록(engine·feature·threshold 버전). **이 시나리오에서 LLM 호출 0회.**
3. 피처 계산 — 풀이시간은 지문 어절 수로 정규화, 유형별 정답률 포함(**축 = 수능 `area_tag` × `type_tag`** — threshold 시트 §1 R6 결정. `item_format`은 분리 리포팅만).
4. 개인 베이스라인 대조(세그먼트 normal).
5. R4 발화: **정답률 유지(83→81%) AND 정규화 시간 1.9배·3주 연속** — 상대 변화 조건.
6. evidence 6건 수집(`EvidenceRef` — 백엔드 DB 원본 논리 참조). 비면 생성 실패.
7. 반 단위 TOP 3~5 상한 적용 — **`new`·`follow_up`에만** 걸고 `ongoing`·`return_care`(R5)는 상한 밖으로 합류시킨다(응답 수·rank가 5를 넘을 수 있음). 데이터 2주 미만 신규생은 조용히 평가 제외 — **목록은 반환하지 않고 `stats.excluded_under_2w` 숫자만**(구 observed_only 제거, 7/16). "관찰 중"(재원 14일 미만) 표시는 백엔드가 `enrolled_at`으로 계산(명세 09 §3).
8. signal(+display_label·lifecycle)+evidence 저장·반환. lifecycle 판정은 AI 소유(명세 09 §4). Alert 승격·상태 관리는 백엔드.

> ✅ **A+BE+FE 확인 완료(2026-07-30) — D1 상한 표현.** TOP 3~5 상한은 `new`·`follow_up`에만 적용하며, `ongoing`과 `return_care`(R5)는 상한 밖으로 추가되어 `signals` 길이와 `rank`가 5를 초과할 수 있다. 백엔드·프론트 모두 응답 길이 ≤5 또는 `rank` ≤5를 가정하지 않는다. 7단계 서술을 정본에 맞춰 동기화했다. 정본: 04 §3 · 09 §4 · 99 #14.

**검증하는 것:** 전체 흐름이 LLM 없이 끊김 없이 도는가. 동일 입력+동일 임계값 버전 = 바이트 동일 출력(결정론). 근거 없는 신호의 물리적 불가능성. → 골든셋 G1~G5.

### 시나리오 D2 — 예외 ①: 신학기 오경보 폭주 방지

**상황.** 3월 2일 학년 진급·반 재편성. 반 전체 지표가 일제히 흔들린다.

1. 학사 이벤트가 스냅숏 메타에 포함되어 도착한다.
2. 해당 학생들의 세그먼트가 `readapt`로 전환 — 4주간 발화 임계 보수화(계수 ×1.3 — threshold 시트 §2).
3. 대부분의 후보가 걸러지되, 명백한 신호(제출 완전 중단 R2)는 살아남는다.
4. 방학 특강은 `vacation` 세그먼트로 분리 계산 — 학습량 급변이 신호로 오인되지 않는다.
5. 수동 개입이 아니라 **베이스라인 계층의 결정론 규칙이 자동** 처리한다.

**검증하는 것:** 계절·학사 오경보가 코드 계층에서 차단되는가. 재적응 중에도 진짜 신호는 사는가. 세그먼트 전환이 이력으로 재현 가능한가. → 골든셋 G6~G8.

### 시나리오 D3 — 예외 ②: 오경보 누적 → 임계값 캘리브레이션 (반자동)

> ⚠ **`/feedback` 보류(7/16)로 이 시나리오는 대기.** 강사 평가 회신 경로가 빠져 자동 피드백 루프가 아직 돌지 않는다. 보류 기간엔 **threshold 시트 §5 섀도 모드 수동 리뷰가 보정 수단** — 캘리브레이션 재개 시 이 시나리오를 활성화한다.

**상황.** 파일럿 4주 차, R3(공부량 급감)의 '해당 없음' 비율이 34%에 도달했다.

1. 강사 평가가 `POST /feedback`으로 회신되어 `rule_feedback` 적재.
2. 주간 배치가 규칙별 비율 계산 — R3이 30% 초과(표본 ≥ 10건 조건 병행).
3. **자동 변경 없음** — 보수화 제안(파라미터 diff+근거 통계, threshold 시트의 보정 범위 내)을 운영자(member-A)에게 상신.
4. 승인 시 `threshold_config` vN+1 저장, 이전 버전 보존 — 과거 경보 재현 가능.
5. 섀도 모드(파일럿 첫 2주)도 동일 루프(발송 스위치만 OFF — D0~D14 체크리스트는 threshold 시트 §5).

**검증하는 것:** 피드백→통계→제안→사람 승인→버전업 루프. 버전 보존에 의한 재현성. 오경보의 학습 재료화.

## B. composition — 소통 초안 + 에이전트 ① + 보조 ⓐⓑⓓ + 핑퐁·리포트

### 시나리오 C1 — 해피패스: 항의성 문의에 라벨 맞춤 답변 초안 (단건 · 선형 유지)

**상황.** 밤 9시, 서연 어머니(라벨: 서사 선호·태도 관심·불안 민감·수시 소통)가 웹뷰로 답장한다. "요즘 아이가 힘들어하는 것 같은데 학원에서는 뭘 하고 있는 건가요?"

1. 백엔드가 문의 도착 즉시 `POST /drafts` 호출 — **강사가 열기 전에 초안이 준비되는 것**이 목표. 초안 1건 = `draft` 할당 1 소모(meta.quota 동봉).
2. **(v2 연결)** 문의 분류(ⓑ)가 먼저 돈다: topic=complaint 계열, urgency=immediate → 완충 강도 상향 + 인박스 최상단 (→ C7).
3. 게이트 ① Consent 통과, ② DataSufficiency 통과(4주 데이터).
4. 컨텍스트 조립(alias): 학습 집계·최근 신호·상담 이력·리포트 열람 이력.
5. 톤 매핑(코드): `tone_map.yaml` 24조합 중 #15 적용 — 서사 선호→과정 중심, 불안 민감→완충 2단계, complaint→완충 상향(매핑표 v0).
6. LLM이 블록 단위 생성 — 블록마다 evidence_refs 인용 강제.
7. 게이트 ③ Evidence ④ SourceGrounding(수치 대조) ⑤ ToneSafety 통과.
8. draft(generated) 저장·반환. **(v3 개정)** 마음에 안 들면 버튼이 아니라 **채팅으로 다듬는다** — /refine 핑퐁(→ C8). **수정·승인·발송은 백엔드(HITL).**
9. 강사 수정 diff는 문체 프로필로 누적.

**검증하는 것:** 분류→게이트→생성→검증의 전체 흐름. 톤 결정이 LLM 재량이 아니라 라벨→파라미터 코드인가. label_snapshot 동결.

### 시나리오 C2 — 예외 ①: 환각 수치 차단 (SourceGrounding)

**상황.** LLM 블록에 "이번 달 정답률 92%"가 들어 있다. 원본은 81%다.

1. 게이트 ④가 인용 ID·수치를 원본과 대조 — 92%는 어떤 레코드와도 불일치.
2. 해당 블록만 실패 판정, 사유 기록("수치 불일치: 92% vs 81%").
3. 실패 블록만 재생성(≤3회). 정정되면 정상 복귀.
4. 3회 소진 시 **섹션 비움 + 사유** — 그럴듯한 문장으로 메우지 않는다.
5. 강사 화면에 "자동 작성 실패 — 직접 작성해 주세요" 정직 표시(에러·상태 코드 사전 §2.1).

**검증하는 것:** 환각이 학부모에게 도달하는 경로의 구조적 부재(게이트가 생성 직후에 있음). 블록 단위 재생성. 재시도 소진의 정직한 착지.

### 시나리오 C3 — 예외 ②: 데이터 부족·데이터 무관 문의 (경계 상태)

**상황 1.** 지난주 등록한 신규생 하윤이의 어머니가 "우리 애 잘하고 있나요?"라고 묻는다(데이터 1주).

1. 게이트 ② DataSufficiency 미달 → **생성 거부는 오류가 아닌 정상 상태**(`rejected_insufficient`+사유).
2. 강사는 직접 답한다 — 어설픈 초안으로 신뢰를 잃지 않는다.

**상황 2.** 민준 아버지: "여름방학 특강 시간표가 궁금합니다"(학습 데이터 무관).

1. 분류(ⓑ)가 topic=schedule로 판정 → `template_only` 경로 — 일반 안내 템플릿만 제안.
2. **빈 근거의 '정상 통과'가 아니라 구분된 상태** — evidence 없는 generated는 여전히 불가.

**검증하는 것:** "생성하지 않음"의 1급 상태 설계. template_only가 EmptyEvidence 원칙의 우회로가 아닌가.

### 시나리오 C4 — 예외 ③: LLM 장애 (복원력)

**상황.** 상담팩 일괄 생성 중 LLM API가 429를 반환하기 시작한다.

1. 게이트웨이(B 소유)가 백오프 재시도 — composition은 결과만 받는다.
2. 소진 시 해당 학생 초안을 `failed(llm_unavailable)`로 기록하고 **다음 학생으로** — 일괄 작업이 죽지 않는다.
3. 에이전트 체크포인트 덕에 장애 해소 후 **실패 학생부터 재개**된다(→ C5).
4. 반환: "22명 중 19 생성 · 2 skip · 1 실패(재시도 예약)". 실패분을 빈 문장으로 메우지 않는다.
5. detection은 LLM 의존 0 — 어떤 LLM 장애에도 야간 배치는 무관.

**검증하는 것:** 부분 실패 격리. 실패의 환각 대체 금지. 제품의 심장(감지) 무영향.

### 시나리오 C5 — 에이전트 ①: 상담팩 오케스트레이터 — 일괄 생성과 중단·재개

**상황.** 7월 14일 상담 주간 D-3. "상담 자료 일괄 생성" 할 일이 뜨고, 김서현 강사가 고1 A반 22명을 대상으로 실행한다(Pro 플랜 월 2회 — 일괄 작업이라 `draft` 할당과 별도).

1. LangGraph 에이전트가 시작된다. `agent_run(counsel_pack)` 생성, 학생 큐 22명 로드(상태 스키마 v0 §1).
2. 학생별 루프: 컨텍스트 수집(코드) → 데이터 충분성(코드 — 신규생 2명은 skip·사유 기록) → **구성 계획(LLM: "서연이는 회복 서사 중심, 민준이는 주의 신호 공유 중심")** — 단, 확정된 수치·신호 안에서 강조점만 고르고 강조점마다 record_id 필수.
3. 블록 생성(LLM) → 게이트 체인(코드) → 실패 블록만 재생성(≤3회).
4. 학생 1명 완료마다 **체크포인트 커밋**(`state_checkpoint`) — draft(counsel_pack, agent_run_id 연결) 저장.
5. 14번째 학생에서 LLM 장애 발생 → `paused` 상태로 정지. **13명분은 이미 안전하게 저장돼 있다.**
6. 30분 뒤 재실행 → 체크포인터가 상태 복원 → **14번째 학생부터 재개**(1~13번 재생성 없음 — 비용·시간 절약).
7. 완료 요약 반환: "22명 중 19 생성 · 2 skip(데이터 부족) · 1 섹션 일부 비움". 모든 노드·판단 이력은 `agent_step` + LangSmith trace로 남는다.
8. 강사가 리포트 스튜디오에서 학생별로 검토·수정·승인 ✋ — 에이전트도 HITL의 예외가 아니다. 개별 초안의 추가 다듬기는 C8과 동일(/refine — 이때부터는 `draft` 할당 소모).

**검증하는 것:** 상태 그래프의 학생별 격리. 중단→재개의 정확성(체크포인트). 계획 노드가 수치를 만들거나 신호를 뒤집을 수 없는가(적대 케이스). 에이전트 산출물도 동일 게이트·HITL을 타는가.

### 시나리오 C6 — 보조 ⓐ: 경보 브리핑 문장화 — 왜곡 게이트와 폴백

**상황.** D1에서 생성된 서연이의 R4 신호가 아침 브리핑에 오른다. 템플릿 문장 대신 자연어 한 줄이 필요하다.

1. detection이 확정한 signal+evidence가 문장화 파이프라인에 입력된다(detection 코드는 무변경 — 소비 측 기능).
2. LLM이 한 줄 생성: "비문학 지문을 붙잡는 시간이 3주째 늘고 있어요 — 정답률은 아직 버티는 중이에요."
3. **왜곡 게이트(코드):** 문장 속 수치·방향·라벨을 코드 확정값과 대조. "3주"·"늘고"·"유지" 모두 일치 — 통과. `signal_brief(gate_passed=true)` 저장.
4. 반례: LLM이 "성적이 급락하고 있어요"라고 쓰면(라벨 반전 — R4는 정답률 유지 신호) 게이트가 차단하고 **템플릿 문장으로 폴백** — 브리핑은 절대 비지 않는다(`fallback_used=true`).
5. 강사가 근거를 펼치면 여전히 원본 6건이 연결되어 있다 — 문장화는 표현이지 근거의 대체가 아니다.

**검증하는 것:** 수치 조작·방향 반전·라벨 뒤집기 주입 테스트. 폴백 경로. detection 무변경. (브리핑은 할당 무관 — 무제한 미터링만.)

### 시나리오 C7 — 보조 ⓑ: 문의 분류 — 인박스 자동 정렬과 오분류의 피해 반경

**상황.** 하루에 문의 6건이 쌓였다: 항의성 1, 성적 문의 2, 일정 문의 2, 상담 요청 1.

1. 각 문의 도착 시 LLM 분류가 돈다: `topic(enum 강제) + urgency + tone`. 구조화 출력 — 자유 텍스트 분류는 파싱 단계에서 불가.
2. 인박스가 자동 정렬된다: 항의성·immediate 최상단, 일정 문의는 template_only 후보로 표시.
3. 분류 결과는 **표시·정렬·완충 강도에만** 쓰인다 — 차단·자동 응답에는 사용하지 않는다(오분류의 피해 반경을 '정렬 순서'로 한정).
4. 강사가 오분류 하나를 원탭 수정 → `corrected_by_teacher` 기록 → 분류 품질 평가셋으로 축적.

**검증하는 것:** enum 강제 파싱. 오분류 피해 반경 계약. 수정 이력의 평가셋 순환.

### 시나리오 C8 — ⚠v3 신규: 채팅형 다듬기(핑퐁) — 강사 지시 vs 게이트

**상황.** C1의 초안이 나쁘지 않지만 아쉽다. 김서현 강사가 초안 아래 채팅창에 쓴다: "마지막에 다음 상담 일정을 제안하는 문장 하나 넣어주세요. 전체적으로 조금 더 짧게."

1. `POST /drafts/{id}/refine`(scope=whole, instruction 자유 문장) — 202. **1턴 = `draft` 할당 1 소모**, 응답 meta.quota로 "이번 달 상담 초안 259/300 남음" 갱신. 세션 턴 상한은 없다.
2. **사전 정적 검사(LLM 호출 전):** 정책 위반 지시(반 평균 비교·실명·PII)는 여기서 차단 — `blocked_reason` 반환, **할당 미소모**(핑퐁 정책서 §5).
3. 통과한 지시는 프롬프트에 조립되어 재생성 — 결과는 **게이트 전체(Evidence·SourceGrounding·ToneSafety) 재통과**. 통과분이 `draft_revision`(블록 스냅숏)으로 저장, revision_no 증가.
4. 반례: 3턴째 "정답률 95%라고 자신 있게 써주세요"(실제 81%) → 생성물이 SourceGrounding에서 탈락 → `evidence_missing` + "요청하신 내용은 기록에서 확인되지 않아 반영하지 못했어요" — **강사 지시가 게이트를 이기지 못한다.** 원문 유지.
5. 복합 지시("짧게 + 반 평균 비교")는 **부분 반영** — 가능한 부분만 적용하고 차단분 사유 동시 반환. 턴을 통째로 버리지 않는다.
6. 5턴째, 강사가 2턴 결과가 더 나았다고 판단 → `{"revert_to": 2}` — 저장된 리비전 복원, **할당 미소모**.
7. 확정되면 승인·발송은 백엔드(HITL — 다듬기는 어디까지나 초안). 지시문은 redaction 통과 후 문체 프로필 재료로 축적(1회성 지시는 미반영 — 반복 패턴만).

**검증하는 것:** 매 턴 게이트 재통과(공격 케이스 A1~A8 — 평가 계획서 §5). 정적 차단의 할당 미소모. 부분 차단. 롤백 정확성(블록 스냅숏 복원). preset(softer 등)+instruction 충돌 시 instruction 승.

### 시나리오 C9 — ⚠v3 신규: 월별·단건 리포트 — 차트 해설과 노출 3층

**상황.** 8월 1일 새벽, 7월분 월별 리포트 일괄 생성이 돈다. 서연이(백분위 68)와 하위권 지훈이(백분위 27, 어머니 라벨 anxious)가 대상에 있다.

1. 백엔드가 **15일 규칙**을 적용한 대상 목록(재원생 전원, 7월 16일 이후 등원생 제외)을 학생별 요청으로 전달 — `kind=report`, 멱등키 `tenant+student+month`, **할당 미소모**(월 1회 일괄).
2. AI의 DataSufficiency 게이트가 **우선**(Open-10) — 목록에 있어도 데이터 2주 미만이면 `rejected_insufficient`(정상 상태).
3. 요청에 백엔드 확정 수치가 실려 온다: 차트 3종(영역별 약점·개선 추이·전국 백분위) + `benchmarks` — `national_percentile(audience=guardian)`과 `class_avg(audience=teacher_only)`.
4. **컨텍스트 조립기가 audience 필터를 프롬프트 조립 전에 적용** — teacher_only(반 평균·석차)는 LLM 입력에 아예 없다. 프롬프트에 없으면 유출이 불가능하다(구조적 제외 — 게이트는 2차 방어).
5. LLM은 `chart_analysis` 블록의 **해설 문장만** 생성 — 블록의 `numbers_used`를 차트 확정 수치와 전수 대조(불일치 → 블록 재생성 ≤3회).
6. 지훈이 리포트: 백분위 27은 **수치 그대로**, 문장은 단독 서술 금지 — 개선 추이·다음 계획과 병기 + anxious라 완곡 2단계, 백분위 해설 블록 후치(매핑표 §3).
7. 학생 화면에는 비교 지표 일절 없음(3층 매트릭스 — 리포트 사양서 §4). 강사가 검토·승인 후 전달(HITL).
8. 별건: 3주 뒤 서연 어머니가 중간 리포트를 요청 → 강사가 단건 발행 — `kind=report_single`, **월 할당(30) + 일일 상한(10)** 소모. 내용 파이프라인은 동일.

**검증하는 것:** teacher_only 유출의 구조적 불가(프롬프트 입력 검사로 테스트). numbers_used 전수 대조. 월별(미소모)/단건(소모) 분기. 15일 규칙 vs 게이트 우선순위. 하위 백분위 완곡 규칙의 라벨 연동.

### 시나리오 L1 — 보조 ⓓ: 라벨 AI 제안 — 근거 인용 강제

**상황.** 민준 아버지와의 소통 이력이 6건 쌓였다. 라벨은 아직 미설정.

1. 주간 배치에서 이력 5건+ 학부모를 대상으로 라벨 추정이 돈다(마스킹·alias 통과분만).
2. LLM 제안: `comm=data(0.86)` — **근거 인용 강제:** "'숫자로 정리해 주세요' 2회(6/12·7/1 문의 인용)".
3. **근거 게이트(코드):** 인용문이 실제 이력에 실존하는지 대조 — 실존하지 않는 인용은 제안 자체가 폐기된다.
4. `label_suggestion(suggested)` 저장 → 학부모 360에 점선 칩으로 표시.
5. 강사가 확정하기 전까지 **초안 생성에 절대 사용되지 않는다**(ai_suggested 미사용 원칙 그대로). 강사 확정 → ai_confirmed.

**검증하는 것:** 인용 실존 게이트(환각 인용 차단). ai_suggested의 초안 미사용 보장. 축 열거형 강제(자유 라벨 불가).

## C. import_mapping — 엑셀 이전 + 에이전트 ② + 보조 ⓒ

### 시나리오 I1 — 해피패스: 타사 CRM 명단·성적 이전 (1-shot · v1 유지)

**상황.** 신규 가입한 박 강사가 타사 CRM에서 내보낸 xlsx(시트 3개, 헤더 "원생명/連락처/週테스트")를 드래그앤드랍한다.

1. 프로파일링(코드) → `source_profile` 저장 → spec 캐시 miss.
2. 마스킹(샘플 ≤20행, 실명·연락처 치환) → LLM 1-shot 추론 → `MappingSpec`(매핑·신뢰도·미매핑 사유). 변환 목적지는 **체크온 표준 스키마**(정의서 #1 — 수능 태그 컬럼 포함).
3. 게이트(Confidence) 통과 → 미리보기 → 강사 수정·**확정 ✋**.
4. 결정론 변환(1,240행 — LLM은 전체 데이터를 본 적 없음) → F1 품질 게이트(성공 1,228/실패 12, 행별 리포트).
5. 백엔드 반영(동의 미보유 행 보류는 백엔드 책임). spec confirmed v1 저장.

**검증하는 것:** LLM 역할의 한정(매핑 추론만). 개인정보 비유입. HITL 확정.

### 시나리오 I2 — 에이전트 ②: 모호한 양식 → 매핑 조사 에이전트

**상황.** 다른 강사의 엑셀은 지독하다: 헤더가 "성명1, 점수A, 점수B, 비고", 명단과 성적이 시트로 분리, 병합 셀 다수. 1-shot 추론 결과 신뢰도가 바닥이다(점수A: 0.41, 제출일: 미매핑).

1. 1-shot spec의 저신뢰·미매핑이 감지되자 **조사 에이전트(LangGraph ReAct)**가 기동된다. `agent_run(mapping_probe)` 생성.
2. 루프 1회차 — LLM이 도구를 선택한다: `get_unique_values("점수A")` → 결정론 도구가 **마스킹 통과** 유니크 값을 반환("8, 7, 10, 9…") → "10점 만점 주간 점수" 가설, 신뢰도 0.41→0.83. (인명 후보 컬럼이면 값 대신 통계만 — 마스킹 정의서 §4.)
3. 루프 2회차 — `check_join_key(명단시트, 성적시트)` → "성명1" 열이 양쪽에서 유일 매칭 → 조인 키 확정(값 미반환 — 일치율만).
4. 루프 3회차 — `get_more_sample("비고", 20행)` → 날짜 패턴 발견 → "비고=제출일" 가설, 신뢰도 0.91.
5. 저신뢰 컬럼이 소진되어 **수렴** — 루프 3회로 종료(상한 5회). 모든 도구 호출·중간 가설은 `agent_step`+LangSmith trace에 남는다.
6. 그래도 미해결인 컬럼("점수B")은 **"모름"으로 명시**된 spec이 나온다 — 억지 매핑 없음.
7. 게이트(Confidence — 점수B '확인 필요' 표시) → 미리보기 → 강사가 점수B를 수동 지정하고 **확정 ✋**.
8. 이후는 I1과 동일: 결정론 변환 → F1 게이트. **에이전트가 조사한 것과 변환하는 것은 완전히 분리**되어 있다.

**검증하는 것:** 도구 루프 상한(5회)과 수렴 조건. 도구가 마스킹 데이터만 반환하는가(구조적 차단). "모름"의 정직한 명시. 조사 이력의 완전한 감사 가능성. 조사와 적용(결정론)의 분리.

### 시나리오 I3 — 예외: 동일 양식 재수입 + 마스킹 이중 방어 (v1 유지)

**상황 1.** 한 달 뒤, 같은 CRM의 새 파일(이번 달치) 업로드.

1. 양식 시그니처 일치 → **LLM·에이전트 호출 0회**로 spec 재사용 → 확정 → 결정론 변환. 동일 파일+동일 spec=동일 결과.

**상황 2.** "비고" 열에 학부모 전화번호가 섞여 있다.

1. masking이 샘플 내 패턴 치환 후에야 LLM·에이전트 도구에 노출. 누락 대비 `redaction`(2차 방어 — 패턴 P1~P8·failure 코퍼스 30건)이 프롬프트·로그 단계 필터링. `LLM_PAYLOAD`에는 마스킹 통과본만.

**검증하는 것:** 재수입의 비용 0·재현성. 1차(masking)+2차(redaction) 이중 방어의 관통(에이전트 도구 경로 포함).

### 시나리오 I4 — 보조 ⓒ: 태깅 제안 — 수능 어휘 · 입력 부담 완화 (v3 개정)

**상황.** 김서현 강사가 트랙 B로 "6월 모의고사 비문학 대비 #3" 채점을 입력한다. 영역·유형 태그 선택이 귀찮다.

1. 과제명 텍스트가 태깅 제안에 입력된다 — `source_text_hash` 캐시 조회. 같은 명명 패턴("비문학 대비 #n")은 **재호출 없이** 캐시 히트.
2. 캐시 miss면 LLM 제안 — **(v3 개정) 수능 6영역 enum 강제**: `area=reading(독서), type=infer, item_format=mcq (0.92)`. area 값은 `reading·literature·speech·writing·language·media`(어휘집 v0 — Open-11 확정 7/15).
3. 경계 사례(융합 지문·화작 통합형 등 — 어휘집 §2)는 confidence를 낮춰 제시 — 과신 금지, 강사 확정에 맡긴다.
4. 입력 화면에 제안 태그가 미리 선택돼 표시, 강사가 원탭 확정(또는 수정 — "언매 문법 N제"를 `language`로).
5. **확정 전에는 learning_event 태그로 반영되지 않는다** — 미확정 태그는 detection 피처(R6)에도 들어가지 않는다.
6. 확정·수정 이력이 태깅 골든셋(평가 계획서 §4)으로 축적. 태그 enum 자체는 B의 약점 지도·출제와 공용 어휘(**[A+B] 승인** — B-3).

**검증하는 것:** 캐시 히트(비용). 미확정 태그의 피처 미반영(감지 오염 방지). 수능 enum + item_format 강제. 경계 사례의 confidence 하향.
