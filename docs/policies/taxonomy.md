# [체크온] 수능 영역·문항 형식 태그 어휘집 v1 — B-3 확정본 `[A+B]`

> **지위:** 6영역 enum과 B-3 경계 사례 7건을 확정한 공용 정본. 코드 enum은 `contracts/taxonomy.py`를 사용하고, 태깅·진단·문제생성은 아래 측정 대상 원칙을 함께 따른다.
> **소비처가 4곳이라 동시 개정 필수:** 감지 R6(오답 유형 편중) · 약점 지도 · 태깅 제안ⓒ · B의 출제/진단 그래프 — 하나라도 다른 어휘로 출발하면 통합 시 재작업.

## 1. `area_tag` — 수능 국어 6영역 (기존 3갈래 대체)

| 값 | 영역 | 정의 | 수능 체제 |
| --- | --- | --- | --- |
| `reading` | 독서 | 비문학 지문 독해(인문·사회·과학·기술·예술·융합) | 공통 |
| `literature` | 문학 | 현대시·현대소설·고전시가·고전산문·극/수필 | 공통 |
| `speech` | 화법 | 발표·토론·협상 등 담화 상황 | 선택 「화법과 작문」 |
| `writing` | 작문 | 글쓰기 계획·초고 수정·자료 활용 | 선택 「화법과 작문」 |
| `language` | 언어(문법) | 음운·단어·문장·담화·국어사 | 선택 「언어와 매체」 |
| `media` | 매체 | 매체 자료의 수용·생산(인터넷·방송 등) | 선택 「언어와 매체」 |

**메타 필드 `subject_track`:** `common`(공통: 독서·문학) | `elective`(선택과목). 영역값에서 유도 가능하지만, **고1·중등처럼 선택 체제가 아닌 학생**의 데이터를 구분하기 위해 별도 필드로 유지한다.

**하위 분류(2차 태그, 선택):** `reading.humanities` `literature.classic_poetry` 식 점 표기 확장을 예약 — v0에서는 6영역만 필수, 하위는 B의 약점 지도 세분화 요구에 따라 v1에서 논의.

### 1.1 기존 3갈래 → 신규 매핑 (마이그레이션)

| 기존 | 신규 | 비고 |
| --- | --- | --- |
| `grammar` | `language` | 1:1 |
| `reading` | `reading` | 값 동일 — 의미 협소화(비문학 한정) 주의 |
| `literature` | `literature` | 1:1 |
| (없었음) | `speech` `writing` `media` | 기존 데이터에는 미태깅 — 태깅 제안ⓒ가 소급 채움 |

### 1.2 중학생·내신 처리 — (7/15 확정) v1 범위 아님, 고도화 항목

타겟을 **수능 대비 고등**으로 좁혔으므로 v1에서 중등 전용 처리(상위 매핑 규칙 등)는 구현하지 않는다. 고도화 시 별도 enum 없이 6영역 상위 매핑(문법→`language`, 비문학→`reading` 등)으로 흡수 가능함만 여기 기록해 둔다 — 스키마 변경 없이 켤 수 있는 구조.

## 2. 경계 판정 사례집 (태깅 제안ⓒ·강사 확정 UI의 기준)

| # | 사례 | 판정 | 근거 |
| --- | --- | --- | --- |
| 1 | 독서 지문 안에 문법 개념 설명(예: 훈민정음 제자 원리 지문) | 문항별 `reading` 또는 `language` | 지문에 제시된 설명의 관계·논리를 독해하면 `reading`, 지문 밖 문법 지식의 적용 자체를 측정하면 `language` |
| 2 | (가) 현대시 + (나) 평론 복합 지문 | 문항별 `literature` 또는 `reading` | 평론을 근거로 작품을 감상·해석하면 `literature`, 평론 자체의 논증 구조·추론을 독립적으로 측정하면 `reading` |
| 3 | 화법+작문 통합형(토론 후 글쓰기) | 문항별 `speech` 또는 `writing` | 담화 참여자·전략·내용 이해는 `speech`, 글쓰기 계획·자료 활용·고쳐쓰기는 `writing` |
| 4 | 매체 자료 속 언어(문법) 문항 | 문항별 `language` 또는 `media` | 문법 지식의 적용을 측정하면 `language`, 매체 자료의 수용·생산 방식과 효과를 측정하면 `media` |
| 5 | 고전시가 현대어 풀이 문항 | 문항별 `literature` 또는 `language` | 작품 문맥의 의미·정서를 해석하면 `literature`, 국어사 형태·어휘 지식을 독립적으로 측정하면 `language` |
| 6 | 융합 지문(과학+예술) | `reading` | 하위 분류 도입 전까지 융합도 `reading` 단일 |
| 7 | 어휘(한자어·속담) 문항 | 문맥 의존 시 지문 영역, 독립 지식이면 `language` | 문맥을 이해해야 의미를 판정할 수 있으면 그 지문의 측정 영역을 따르고, 문맥 없이 어휘·한자어·속담 지식을 직접 측정하면 `language` |

**원칙 요약:** ① 세트가 아닌 **문항 단위**로 태깅 ② 지문 소재·자료 형식이 아니라 **측정 대상(무엇을 묻나)** 기준 ③ source/passage의 소재 영역과 문항의 measured area를 분리 ④ 애매하면 태깅 제안ⓒ가 `confidence`를 낮춰 제시하고 강사 확정에 맡긴다(자동 확정 금지 — 기존 규약 그대로).

`area_tag`는 measured area만 담는다. 지문 소재·출처·갈래는 `PassageDomain`, 작품 메타 또는 Import 원본 메타처럼 별도 source/passage 필드에 보존하며, 이 값을 `area_tag`로 복사해 자동 판정하지 않는다. 혼합 지문도 자료 전체에 단일 영역을 부여하지 않고 각 문항의 측정 대상에 따라 태깅한다.

### 2.1 v1 문제생성 세트 제한

v1 자동 문제생성의 `ProblemRequest.area_tag`는 **세트당 하나**다. 세트에 속한 모든 `GeneratedItem.area_tag`는 이 요청값과 같아야 하며, 화법+작문처럼 서로 다른 measured area의 문항을 한 요청에서 섞는 자동 생성은 지원하지 않는다. 혼합 자료의 문항별 태깅은 Import·태깅 제안에서 허용하되, 혼합영역 자동 세트 생성은 후속 다중 목표 계약을 별도로 승인한 뒤 도입한다.

## 3. `type_tag` — 인지 유형 (area와 직교, 변경 없음)

`fact`(사실 확인) | `infer`(추론) | `critic`(비판·평가) | `concept`(개념·지식) | **`apply`(적용·창의 — 🔴 v1 미산출 · 어휘 예약)**. 모든 area와 조합 가능 — 예: `literature × infer`(화자 정서 추론), `language × concept`(음운 규칙 지식).

🔴 **`apply` 예약(8/8 · 99 ㊣) — 평가원 5축을 계약에 담되 v1 산출은 4종이다.** `item_format`의 `short`·`essay`와 같은 예약이지만 **처방이 다르다** — `item_format`은 요청 파라미터라 우리가 만들지 않지만 `type_tag`는 **여러 문으로 들어온다.** 문마다 답이 다르다:

| 문 | v1 처방 | 근거 |
| --- | --- | --- |
| **산출**(우리가 만든다) | **안 낸다** | 골든셋에 `apply` 표본이 없어 검증 불가(99 ㊛). ⚠ 실측상 **산출하는 자리 자체가 없다** — `composition/classify/`에 `TypeTag` 참조 0건 |
| **출제 요청**(BE → `ProblemRequest.type_tags`) | **400 `type_tag_not_supported`** `[제안 · B 구현 대기]` | 주체 3분할 — 호출자가 요청을 고쳐야 한다(`source_procurement_not_implemented` 선례). **구현은 B 몫**. 🔴 **구현 전인 지금은 400이 아니라 HTTP 500 + 조회 불가 잡이다**(99 ㊨ 실측) |
| **학습 이벤트**(BE → `LearningEvent.type_tag`) | 🔴 **받는다** | 강사가 매긴 태그가 흘러온 것이고 **우리 v1 범위와 무관한 사실**이다. 막으면 구현 범위 때문에 데이터를 왜곡하고 ㊛의 재료를 만들 경로를 닫는다 |
| **완전성 검사**(`difficulty_weights`) | 가중치를 **안 갖는다** | 보정 미배선(`difficulty_regen_enabled: false`)인데 `0.0`을 넣으면 *"적용·창의는 난이도 가산 0"* 이라는 **없는 사실**이 생긴다 |
| **표시 라벨**(`_TYPE_KO`) | 🔴 **갖는다**(`"적용"`) | 학습 이벤트를 받는 이상 R6 브리핑까지 흘러간다. 라벨이 없으면 `.get()` 폴백이 **영문**이라 *"문학·apply"* 가 학부모 문장에 섞이고 **게이트가 못 막는다** |

⚠ **아래 §5의 「소비처 4곳 동시 개정 필수」는 이 예약에 해당하지 않는다** — 그 규약은 **산출 어휘가 바뀔 때**의 것이고, 예약은 **산출을 안 늘린다.** 실제로 이 개정은 4곳 중 어디도 안 건드렸다(태깅 프롬프트·골든셋·threshold 시트·표시 매핑 중 **표시 매핑만** 라벨을 얻었고 그건 누출 방지다).

**여는 조건:** 99 ㊛ 태깅 골든셋에 `apply` 표본이 쌓이고 baseline이 정해질 때. 그날 `V1_TYPE_TAGS`가 자동으로 넓어지고 `verify_config.yaml`이 red를 내서 가중치를 같이 넣게 된다.

## 4. `item_format` — 문항 형식 (신규 축)

> **(7/15 회의 확정)** v1은 **`mcq`(객관식)만 사용** — 수능 국어는 전 문항 객관식이므로. `short`·`essay`는 **enum 자리만 예약**(내신·자체 시험 대비는 타겟 고도화 단계 — F17과 함께 재론). 아래 표의 short·essay 행은 그 시점의 사양이다 — **서술형 채점 분담은 폐기된 안건**(99_open_items B-4 참조: v1은 mcq만이라 서술형 채점 자체가 없음).

| 값 | 형식 | 채점 | AI 관여 |
| --- | --- | --- | --- |
| `mcq` | 객관식(5지선다) | 자동(정오) | 없음 — 정오만 피처로 |
| `short` | 단답형 | 자동(문자열 매칭) + 유사 답안은 강사 확인 | 유사 답안 후보 제시 `[제안]` |
| `essay` | 서술형 | **루브릭 1차 제안 → 강사 확정** | LLM이 루브릭 기준별 채점 초안 + 근거 문장 인용. **확정 전 점수는 피처·리포트에 미반영** |

**서술형 채점 분담 — 폐기된 안건 (99_open_items B-4 참조).** v1은 mcq만 쓰므로 서술형 채점이 존재하지 않는다. 아래는 타겟 고도화 시점에 재론할 때의 출발점으로만 남긴다: 루브릭 생성·채점 초안 = **B**(출제·진단 소유) · 확정된 채점 결과를 감지 피처(R1·R6)·리포트 문장으로 소비 = **A** · 경계는 "확정 이벤트"(백엔드가 강사 확정 시점에 learning_event로 발행). **이 분담대로 코드를 만들지 말 것** — `contracts/taxonomy.py`의 `short`·`essay`는 처리 분기 금지 예약값이다.

**R6 집계 축 (문서 #3 threshold 시트와 연동):** v0 제안 = `area_tag × type_tag` 기본 + `item_format`은 **분리 리포팅만**(편중 판정 축에는 미포함 — 셀이 6×4×3=72개로 쪼개지면 학생당 표본 부족). 파일럿 데이터로 재평가.

## 6. B-3 합의 결과

1. 6영역 enum + `subject_track` + `item_format` 어휘를 유지한다.
2. §2 경계 사례 7건은 측정 대상 기준으로 확정하며 태깅 골든셋의 시드로 사용한다.
3. source/passage 메타와 measured `area_tag`를 분리하고, 혼합 지문은 문항 단위로 판정한다.
4. v1 문제생성 세트는 §2.1과 같이 단일 measured area로 제한한다.
5. ~~§4 서술형 분담(B-4)~~은 폐기하고 R6 집계 축만 유지한다.
