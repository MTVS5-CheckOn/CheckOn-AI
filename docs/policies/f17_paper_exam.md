# [체크온] F17 지면 시험·스캔 채점 — 사전 설계 메모 v0 (Phase 2)

> **지위:** 지금 구현하지 않는다(Could · Phase 2). 이 메모의 목적은 하나 — **Phase 1 스키마에 지금 박아둘 필드를 확정**해서 Phase 2 때 마이그레이션 대공사를 피하는 것. 1~2쪽 유지.

---

## 1. 루프 전체 (기획서 F17 확정 흐름)

```
① 강사 문제 준비 (자작 문제 + LLM 핑퐁 논의로 보완)
② PDF 조판·인쇄 → 오프라인 시험
③ 답안지 스캔/촬영 업로드
④ OCR 판독 → ⑤ LLM 1차 채점·해설 초안 → ⑥ 강사 검수·확정
⑦ 확정분이 learning_event로 유입 → 감지 피처·약점 지도·리포트 반영
```

강사 자작 문제·수기 채점본 스캔도 같은 ④~⑦ 경로로 흡수(문제 원본이 체크온 밖에서 났어도 결과는 데이터로).

## 2. OCR 단계화 로드맵 — 한 번에 손글씨로 가지 않는다

| 단계 | 대상 | 난이도 | 판독 방식 |
| --- | --- | --- | --- |
| P2a | **OMR형 객관식**(마킹 칸) | 낮음 | 템플릿 정합 + 마킹 검출 — LLM 불필요 |
| P2b | **단답형**(짧은 활자·정자) | 중간 | OCR + 정답 문자열 매칭, 유사 답안은 강사 확인 큐 |
| P2c | **손글씨 서술형** | 높음 | OCR + LLM 루브릭 채점 초안(B 소유) — 파일럿 후 |

**정직 처리 원칙:** 판독 confidence < 임계 → 해당 답안 `unreadable`로 표기하고 **추측 금지** — 강사 수기 입력 폴백 큐로. "몰래 틀린 값"이 감지 피처를 오염시키는 것이 최악 시나리오.

## 3. 실명 문제 — Open-12 (백엔드 vault 전제)

답안지에는 학생 실명이 손글씨로 적혀 있다. AI는 alias-only 원칙이므로:

- **제안 A(기본):** 백엔드가 스캔 수신 → 이름 영역만 vault에서 매칭(실명→alias) → **이름 영역 마스킹/크롭된 이미지 + alias**를 AI에 전달. AI는 실명 픽셀 자체를 받지 않는다.
- 제안 B(대안): 시험지 템플릿에 학생별 식별 QR/번호를 인쇄해 이름 판독 자체를 제거 — 체크온이 PDF를 조판하는 경우(②) 무료로 얻는 설계. **A 추천: 둘 다** — QR 기본, 자작 시험지(QR 없음)만 제안 A 경로.
- 어느 쪽이든 실명 매칭 소유는 백엔드(Open-12) — AI 경계는 "alias + 마스킹 이미지 수신"으로 고정.

| 조각 | 소유 |
