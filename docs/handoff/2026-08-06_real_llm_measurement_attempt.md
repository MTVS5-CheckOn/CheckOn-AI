## 2. 🔴 측정 불가 원인 — 서버가 502입니다

`/v1/models`에 **7회** 요청했고 전부 `HTTP 502`였습니다. 응답 본문이 Cloudflare 오류 템플릿
(`no-js ie6 oldie` 클래스)이라 **프록시가 살아 있고 그 뒤 추론 서버가 죽어 있는** 형태입니다.

| 확인 | 결과 |
| --- | --- |
| provider 어댑터 1회 호출 | `LlmUnavailable` — "로컬 LLM 서버 오류 502"(1.1s) |
| `GET /v1/models` 3회(20초 간격) | 502 · 502 · 502 |
| `GET /v1/models` 4회(30초 간격, 02:19~02:21) | 502 · 502 · 502 · 502 |

⇒ **일시적 장애가 아닙니다.** 어댑터는 502를 `LlmUnavailable`(5xx → 503 매핑)로 올려
계약대로 동작했습니다 — AI 코드 문제가 아닙니다.

### 서버 담당께 요청

추론 서버 기동 후 알려주시면 같은 회차를 그대로 돌립니다. 소요는 8/4 실측 기준
**호출 34건 · 수 분**입니다.

## 3. 🔴 서버가 살아나도 남는 차단 요인 2건

서버 문제와 **별개로** 러너 쪽에 두 건이 있습니다. 이번에 발견했고 **이 PR에서 고치지
않았습니다**(측정 PR에 수정이 섞이면 어느 버전의 수치인지 알 수 없습니다 — 지시서 금지사항).
99에 등재만 했습니다.

### ① 🔴 (하드 차단) `classify_eval`이 **confidence를 기록하지 않는다** — 측정 A 불가

측정 A는 **confidence 구간별 실제 정확도**를 요구합니다. 그런데 러너가 케이스별로 남기는
것은 이것뿐입니다.

```python
rows.append({
    "expected": [...], "actual": [...], "classified": result.classified,
})
```

`ClassifyResult.confidence`(3축)가 **어디에도 안 들어갑니다.** 축별 정확도 총합만 나옵니다.

⇒ **서버가 살아나도 이 러너로는 ⓐ를 측정할 수 없습니다.** 구간 표를 만들려면 러너가
축별 confidence를 행에 남겨야 하고, 그건 **코드 변경**이라 별 PR입니다(99 ⓝ).

> 원인 추정: 이 러너는 §7 합격 기준(정확도·재현율)을 보려고 만들어졌고, ⓐ의 캘리브레이션은
> 나중에 붙은 요구입니다. 러너가 틀린 게 아니라 **용도가 하나 늘었습니다.**

### ② ⚠ (소프트 차단) `counsel_llm_smoke`가 **8/4 리포트를 덮어쓴다**

```python
_REPORT_PATH = Path("docs/handoff/2026-08-04_llm_smoke_report.md")   # 모듈 상수
...
parser.add_argument("--date", default="2026-08-04", help="리포트 표기용 실행일")
```

`--date`는 리포트 **본문의 `run_date` 표기**만 바꿉니다. 경로는 상수라 **어느 날짜로 돌려도
8/4 파일에 씁니다.** 러너 docstring도 "재실행하면 통째로 덮어쓴다"고 이미 경고합니다.

이번 지시서는 *"8/4 리포트를 수정하지 말 것 — 그 날짜의 실측 기록이다"* 를 금지사항으로
걸었으므로, 그대로 실행하면 **지시를 위반**합니다.

**회피는 가능합니다**(실행 후 `git checkout -- docs/handoff/2026-08-04_llm_smoke_report.md`)
— 그래서 하드 차단이 아닙니다. 다만 실행이 중간에 죽으면 파일이 깨진 채 남고, "새 회차는 새
파일" 규율(#92에서 세운 것)과도 어긋납니다. **경로에 실행일을 반영하는 것이 옳습니다**(99 ⓝ).

## 4. 서버 복구 후 실행 순서 (그대로 쓰시면 됩니다)

```bash
# ⓪ 추적 비활성 재확인 — 이 확인 없이 돌린 회차는 근거로 쓰지 않는다

#    False 가 아니면 즉시 중단

# ① 분류 평가 — 측정 B(폴백률)·§7 합격 기준. 산출은 local_data/(gitignore)

git checkout -- docs/handoff/2026-08-04_llm_smoke_report.md   # ⚠ §3-② 회피
```

측정 A는 **99 ⓝ ①(러너에 confidence 기록 추가)이 먼저 머지된 뒤**에 가능합니다.

### 측정별 획득 가능성 (코드 읽어 확인)

| 측정 | 필요한 산출 | 현 러너가 내는가 |
| --- | --- | --- |
| **A** ⓐ confidence 구간별 정확도 | 케이스별 3축 confidence | 🔴 **아니다** — ⓝ ① 선행 |
| **B** ⓔ 폴백률 + 사유별 | `unclassified` 수 · `fallback_reason` | ✅ 낸다(`classify_eval`) |
| **C** ㊼ seed 2회 대조 | `identical`·`len_first`·`len_second` | ✅ 낸다(S5) |
| **D** ㊴ `blocked_reason` 빈도 | `blocked_reason`·`expected_reason`·`applied` | ✅ 낸다(S3) |

즉 **B·C·D는 서버만 살아나면 즉시**, A는 러너 보완이 먼저입니다.
