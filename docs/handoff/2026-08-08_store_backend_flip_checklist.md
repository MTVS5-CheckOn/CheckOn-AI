# `store_backend=pg` 플립 점검표 — A 축에서 무엇이 달라지는가 (A → B)

**작성 2026-08-08 · A(member-A) · 플립 주체는 준영님(선행조건 CI 녹색)**

🔴 **이 문서는 판정이지 수정이 아니다.** 아직 안 뒤집혔으므로 어느 칸도 99에서 ✅로
적지 않았다 — *"닫힌다"* 를 *"닫혔다"* 로 적을 수 없다(로그 43).

## 0. 플립이 실제로 바꾸는 것 — 전수

`store_backend == "pg"` 분기는 **팩토리 아홉 + 체크포인터 하나**다(실측 8/8):

| 자리 | 플립하면 |
| --- | --- |
| `db/store_factory.py` — `build_*` **아홉** | 각 `Pg*Store`로 바뀐다(잡 원장 · 멱등 · 감지 · 프로필 · spec · 스텝 · 실행 원장 · 문의반 · **팩 결과**) |
| `composition/counsel/assembly.py:130` | `AsyncPostgresSaver`(체크포인터) |
| `import_mapping/probe/assembly.py` · `problem_generation/assembly.py` | 각 capability의 저장소·체크포인터 |

🔴 **바뀌지 않는 것이 이 표의 핵심이다** — `api/routers/counsel.py`의 **`_view_cache`·
`_drafts`는 모듈 전역 dict이고 `store_backend` 분기를 타지 않는다**(실측: 그 두 이름이 있는
줄에 `store_backend`·`build_` 언급 **0건**). ⇒ **플립은 「읽기 모델」을 영속화하지 않는다.**

## 0-1. 🔴 **플립 전 관문 셋 (2026-08-10 신설 · A+B 판정 #36)**

**아래 셋이 서기 전에는 `STORE_BACKEND=pg`를 켤 수 없다.** 아래 §1의 안건들과 성격이 다르다 —
저건 *"플립하면 닫히는가"* 이고 이건 ***"플립이 되기는 하는가"*** 다.

| # | 관문 | 소유 | 상태 |
| --- | --- | --- | --- |
| **G1** | `AGENT_RUN.run_id` **nullable 모델·마이그레이션 머지** | 🔴 **B(준영님)** | ☐ 대기 |
| **G2** | **종단 + 실제 LLM 호출을 소비한 경로**에서 `AI_RUN` 누락 가드 | 🔴 **B(준영님)** | ☐ 대기 |
| **G3** | counsel · probe · problem_generation **실제 enqueue 재검증**(실 PG) | **A** | ☐ G1 뒤 |

🔴 **G1 없이는 첫 요청부터 죽는다** — 실측(8/10 · Fake provider · 실 LLM 0):
`POST /v1/counsel/drafts` → **HTTP 500** · `SQLSTATE 23503` · `fk_agent_run_run_id_ai_run`.
**세 워커가 같은 `PgJobStore.add()`** 를 지나므로 **셋 다** 막힌다(99 #36).

🔴 **G2가 G1의 조건이다.** nullable은 「없어도 된다」를 여는 변경이라, **없어도 되는 경우와
없으면 안 되는 경우**를 가르는 가드가 함께 서지 않으면 **결함을 감추는 변경**이 된다.
종전 기준(*"`AGENT_RUN`이 있으면 `AI_RUN`이 반드시 있다"*)은 **거짓**이었다 —
`queued`·`template_only`·근거 0건·`pause`·`fail`이 전부 반례다.

⚠ **G3를 「관측」으로 대체하지 마라** — 지금까지 PG 왕복 테스트가 **손으로 `AI_RUN` 부모를
선삽입**해서 이 결함을 못 봤다. **실제 enqueue 경로**로 다시 확인해야 한다.

### ⚠ `mapping_probe`의 `AI_RUN`은 **이 관문이 아니다** (99 ㉾)

`mapping_probe`는 `record_run()` 호출이 **0건**이라 `AI_RUN`이 영영 안 생긴다.
🔴 **G1이 서면 enqueue 차단은 풀리지만 그 사실은 그대로 남는다** ⇒ **별도 A 작업**이다.

⚠ **그러므로 전면 플립 성공을 「모든 실행 원장이 완성됐다」로 부르면 안 된다.**
플립이 여는 것은 **잡이 PG에 앉는 것**이고, **㉾와 불변식 8은 그때도 안 닫힌다.**

## 2. 🔴 「PG 이관」이 두 가지를 가리킨다

㉿·㉻의 여는 조건이 *"PG 이관"* 인데 그 말이 **둘**이다:

| 뜻 | 무엇 | 상태 |
| --- | --- | --- |
| **ⓐ 백엔드 플립** | `store_backend=pg` — 팩토리 아홉 + 체크포인터 | 준영님 축 · 임박 |
| **ⓑ 읽기 모델 영속** | `_view_cache`·`_drafts` → 06 §7 `DRAFT_REVISION` | **미착수** · 별 축 |

⇒ **ⓐ가 와도 ㉿·㉻은 안 닫힌다.** 두 안건의 여는 조건은 **ⓑ**다.
⚠ 갈라 적지 않으면 플립 직후 *"PG로 갔는데 왜 404가 그대로냐"* 가 된다.

### 🔴 (8/9 갱신) ⓑ에 **여는 조건이 한 겹 더 있다** — 스키마 결정

PR-μ가 ⓑ에 착수했다가 **관문에서 멈췄다.** 테이블(`draft`·`draft_revision`)은 이미 있는데
**모양이 안 맞는다** — `_CachedView`(3) 전부와 `_DraftState`(5) 전부, `DraftContext` 하위
**5/8**, 그리고 기존 `DraftRecord`의 **`content`(본문)** 가 갈 컬럼이 없다.
⇒ **배선이 아니라 컬럼 추가나 테이블 신설이 필요하고 그건 양자 + 마이그레이션**이다.

⚠ **ⓐ(컬럼 추가)를 골라도 `_CachedView` 셋은 남는다** — 응답 뷰라서 도메인 행에 안 맞는다.
⇒ **ⓐ 단독으로는 ㉿가 안 닫힌다.**

**선택지와 실측 전수는 `docs/handoff/2026-08-09_read_model_persistence_schema_ask.md` 에 있다** —
🔴 **A가 고르지 않았다**(㉕와 같은 형태의 협의 안건).
⚠ 두 테이블은 **프로덕션 쓰기가 0건**이라(전수) 모양이 맞는지 확인할 기회가 없었다 — #22 형태.

⚠ **㉿를 「캐시 축출·재시작 후 404」로 부르는 것은 안건이 달라서가 아니다** — 99의 ㉿는
제목이 *"§3.9의 v1 한계가 문서에 없었다"* 이고 **본문이 그 한계들**(캐시 상한 256 · 축출 시
404 · GET은 404인데 refine은 200 · 재시작 비대칭)이다. **제목으로 부르면 문서 결함, 본문으로
부르면 캐시 결함**이라 같은 안건의 두 이름이다. ⚠ #15(끊긴 인용)과 **다르다** — 가리키는
대상이 실재한다. ⚠ **(8/9 정정) `잔여작업_2026-08-08.md`는 레포가 아니라 프로젝트 쪽에 있다** — A 지시서가 위치를
틀렸고 A도 `docs/` 아래만 훑었다. 준영님 확인: 그 문서 C절이 ㉿를 *"캐시 축출·재시작 후 404 —
잡 원장은 살아 있는데 본문을 못 돌려준다"* 로 쓴다. ⇒ **99 ㉿ 본문 그대로**이고 **같은 안건의
두 이름** 판정이 유지된다. 정정할 것 없음.

## 3. ⚠ 플립 직후 관측 둘이 **반대로** 움직인다

```
job_ledger_size · job_ledger_added   →  수    →  None    (인메모리 원장이 사라진다)
pack_miss_absent · pack_miss_foreign →  None  →  수      (PG 저장소가 세기 시작한다)
```

🔴 **둘 다 정상이다.** 앞은 `InMemoryJobStore`가 아니면 `None`을 내고(*"PG인데 0건"* 과
*"인메모리라 안 센다"* 를 가르려고), 뒤는 `PgPackResultStore`만 카운터를 든다.
⚠ **안 적으면 「관측이 깨졌다」로 읽힌다** — 방향이 반대라 더 그렇다.

**플립 직후 스모크에서 볼 것:**

| 값 | 기대 |
| --- | --- |
| `job_ledger_size`·`job_ledger_added` | **`None`** — 수가 남아 있으면 **플립이 안 먹은 것**이다 |
| `pack_miss_absent`·`pack_miss_foreign_tenant` | **수**(0 포함) — `None`이면 팩 저장소가 인메모리다 |
| `emphasis_scanned` | **0이 아니어야 한다**(PR-ι 배선 미확인 · 플립과 무관) |
| `view_cache_evicted`·`draft_cache_evicted` | 🔴 **0이 아니면 ㉿가 실제로 밟히고 있다**(8/9 신설 · 플립과 무관) |

⚠ **축출 카운터 둘은 `None`이 아니라 항상 수다** — 읽기 모델 캐시는 `store_backend`와 무관한
모듈 전역이라 `0`은 *"안 센다"* 가 아니라 **"축출이 없었다"** 다(`job_ledger_*`와 다른 성질).
🔴 **둘을 갈라 센다** — ㉿의 *"GET은 404인데 refine은 200"* 이 **두 캐시의 독립 축출**이고
합치면 그 비대칭이 리포트에서 사라진다.

## 3-1. 🔴 PG에서만 확인되는 것 둘 (PR-λ의 마지막 미검증)

**#24의 수정은 「결정론 id + 결정론 시각」 둘이고 그 필요성은 확인됐다.** 다만 **멱등 분기
자체는 `PgPackResultStore`에만 있다** — `InMemoryPackResultStore.put`은
`self._rows[record.id] = record`로 **그냥 덮어쓴다**(실측). ⇒ 단위 하네스(인메모리)가
보는 범위는 **「같은 키 + 첫 시각 유지」까지**다.

| 확인할 것 | 어디서 | 왜 PG여야 하나 |
| --- | --- | --- |
| ⓐ **재시도가 멱등 분기에 흡수되는가** — 같은 `id`·같은 내용 재저장이 **행을 늘리지 않고** 같은 ref를 돌려주는가 | `test_pack_result_pg_roundtrip.py::test_the_same_id_is_not_silently_overwritten` (**로컬 skip**) | 인메모리는 분기가 없어 **덮어써도 행이 하나**다 — 「분기가 흡수했다」와 구분이 안 된다 |
| ⓑ **시각이 다르면 `PackResultConflict`가 나는가** | 같은 파일 | 🔴 *"결정론 시각이 아니면 고아 대신 실패가 된다"* 의 **인과가 PG에서만 재현된다.** 인메모리는 조용히 덮인다 |

⚠ **수정이 틀렸을 가능성을 말하는 것이 아니다** — 둘 다 필요한 것이 맞다. **검증 범위가
인메모리까지**라는 사실을 적는 것이고, ⓐⓑ가 확인되면 이 PR의 미검증이 닫힌다.

## 4. 플립 전에 A 축에서 남은 것

**코드로 남은 것은 없다.** #24가 PR-λ로 닫혔고 ㉕(팩 결과 PG)는 PR-κ가 닫았다.

만들지 않는다(㉬는 오히려 절반이 좋아진다).
