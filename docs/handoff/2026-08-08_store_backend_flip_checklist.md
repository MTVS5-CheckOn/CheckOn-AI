**작성 2026-08-08 · A(member-A) · 플립 주체는 준영님**

⚠ **선행조건은 「로컬 `pre_pr_verify` 통과」다**(#204 이후) — 종전엔 *"CI 녹색"* 이라 적었는데

## 0. 플립이 실제로 바꾸는 것 — 전수

`store_backend == "pg"` 분기는 **팩토리 아홉 + 체크포인터 하나**다(실측 8/8):

| 자리 | 플립하면 |
| --- | --- |
| `db/store_factory.py` — `build_*` **아홉** | 각 `Pg*Store`로 바뀐다(잡 원장 · 멱등 · 감지 · 프로필 · spec · 스텝 · 실행 원장 · 문의반 · **팩 결과**) |

| `import_mapping/probe/assembly.py` · `problem_generation/assembly.py` | 각 capability의 저장소·체크포인터 |

🔴 **바뀌지 않는 것이 이 표의 핵심이다** — `api/routers/counsel.py`의 **`_view_cache`·

줄에 `store_backend`·`build_` 언급 **0건**). ⇒ **플립은 「읽기 모델」을 영속화하지 않는다.**

### 🔴 (8/9 갱신) ⓑ에 **여는 조건이 한 겹 더 있다** — 스키마 결정

## 3. ⚠ 플립 직후 관측 둘이 **반대로** 움직인다

```
job_ledger_size · job_ledger_added   →  수    →  None    (인메모리 원장이 사라진다)
pack_miss_absent · pack_miss_foreign →  None  →  수      (PG 저장소가 세기 시작한다)
```

🔴 **둘 다 정상이다.** 앞은 `InMemoryJobStore`가 아니면 `None`을 내고(*"PG인데 0건"* 과
*"인메모리라 안 센다"* 를 가르려고), 뒤는 `PgPackResultStore`만 카운터를 든다.
⚠ **안 적으면 「관측이 깨졌다」로 읽힌다** — 방향이 반대라 더 그렇다.

**플립 직후 스모크에서 볼 것:**

| 값 | 기대 |
| --- | --- |
| `job_ledger_size`·`job_ledger_added` | **`None`** — 수가 남아 있으면 **플립이 안 먹은 것**이다 |
| `pack_miss_absent`·`pack_miss_foreign_tenant` | **수**(0 포함) — `None`이면 팩 저장소가 인메모리다 |
| `emphasis_scanned` | **0이 아니어야 한다**(PR-ι 배선 미확인 · 플립과 무관) |
| `view_cache_evicted`·`draft_cache_evicted` | 🔴 **0이 아니면 ㉿가 실제로 밟히고 있다**(8/9 신설 · 플립과 무관) |

⚠ **축출 카운터 둘은 `None`이 아니라 항상 수다** — 읽기 모델 캐시는 `store_backend`와 무관한
모듈 전역이라 `0`은 *"안 센다"* 가 아니라 **"축출이 없었다"** 다(`job_ledger_*`와 다른 성질).
🔴 **둘을 갈라 센다** — ㉿의 *"GET은 404인데 refine은 200"* 이 **두 캐시의 독립 축출**이고
합치면 그 비대칭이 리포트에서 사라진다.

## 3-1. 🔴 PG에서만 확인되는 것 둘 (PR-λ의 마지막 미검증)

**#24의 수정은 「결정론 id + 결정론 시각」 둘이고 그 필요성은 확인됐다.** 다만 **멱등 분기
자체는 `PgPackResultStore`에만 있다** — `InMemoryPackResultStore.put`은
`self._rows[record.id] = record`로 **그냥 덮어쓴다**(실측). ⇒ 단위 하네스(인메모리)가
보는 범위는 **「같은 키 + 첫 시각 유지」까지**다.

| 확인할 것 | 어디서 | 왜 PG여야 하나 |
| --- | --- | --- |
| ⓐ **재시도가 멱등 분기에 흡수되는가** — 같은 `id`·같은 내용 재저장이 **행을 늘리지 않고** 같은 ref를 돌려주는가 | `test_pack_result_pg_roundtrip.py::test_the_same_id_is_not_silently_overwritten` (**로컬 skip**) | 인메모리는 분기가 없어 **덮어써도 행이 하나**다 — 「분기가 흡수했다」와 구분이 안 된다 |
| ⓑ **시각이 다르면 `PackResultConflict`가 나는가** | 같은 파일 | 🔴 *"결정론 시각이 아니면 고아 대신 실패가 된다"* 의 **인과가 PG에서만 재현된다.** 인메모리는 조용히 덮인다 |

⚠ **수정이 틀렸을 가능성을 말하는 것이 아니다** — 둘 다 필요한 것이 맞다. **검증 범위가
인메모리까지**라는 사실을 적는 것이고, ⓐⓑ가 확인되면 이 PR의 미검증이 닫힌다.

## 🔴 플립했다 (2026-08-12 · 99 #39)

**선언 기본값이 `pg`다.** 실 PG · 환경 변수를 지운 기본 설정 · **서로 다른 앱 인스턴스**로 쟀다.

| 잰 것 | 결과 |
| --- | --- |
| 팩토리 **11종** 기본 조립 | **전부 PG** · 명시 `memory`에서 **전부 종전 구현** |
| `store_backend` 분기 **15곳** | 팩토리 11 + 안 부르는 4곳(**사유 명시** — `_open_saver` 셋은 커넥션을 여는 async 컨텍스트) |

| 부모 없는 `AGENT_STEP` | **FK가 거부한다**(G1이 지운 것은 `agent_run.run_id → ai_run` **하나**다) |

🔴 **「pg로 켰다」와 「전부 PG다」는 다른 사실이다.** `api/routers/counsel.py`의
**`_context_store`·`_draft_store`는 초기값도 reset도 인메모리 리터럴**이라 `store_backend`
분기를 **아예 안 탄다**(위 §0의 「바뀌지 않는 것」에 **두 줄이 더 있었다**). 그래서
**다른 프로세스의 워커는 잡을 실행조차 못 한다** — 실측 `error_code=context_bundle_missing`.
인메모리 저장소를 손으로 인계해 완주시켜도 GET은 **`result=None`**이다.
⚠ **PG 구현을 만들 수 없다** — `ContextBundleRecord`는 대응 테이블이 없고
`DraftRecord.content`는 갈 컬럼이 없다(㉿가 8/9에 실측한 그 결손) ⇒ **양자 승인 + 마이그레이션**.
