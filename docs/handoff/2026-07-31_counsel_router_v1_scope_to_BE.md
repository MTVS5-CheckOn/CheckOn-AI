# [A → BE·FE] counsel 초안 API v1 구현 범위 정정 5건 (인박스 계약 v1 §4)

**보낸이:** 박진희(AI-A) · **날짜:** 2026-07-31 · **관련:** 인박스 데이터계약 v1 §4 · 라벨 검토함 계약 §2·§6 · `ai docs 04` §3.9 · `part_a/05` §7
**대상:** 백엔드(승우) · 프론트

어제 확정 통보로 나간 계약을 **조용히 밑돌지 않으려고** 먼저 알립니다. ①②는 계약보다 **낮게** 구현된 부분이고, ③은 영향 없음, ④⑤는 **계약 예시·표기의 정정**입니다.

---

## ① `citations[]` — 각주형 목록입니다. 본문 인라인 앵커(`#L1`)는 v1.1

계약 §4-③ 예시가 이렇게 돼 있습니다.

```json
"text": "어머님, 먼저 세심하게… #L1 …",
"citations": [ { "cite_id": "L1", "record_id": "le_2041", … } ]
```

**v1은 본문에 `#L1`을 넣지 않습니다.** 이유는 두 가지입니다.

1. **`#`이 초안 게이트의 금지 기호입니다.** `_SYMBOL_RE = [$\\`*#_~^{}]` — LaTeX·마크다운 유출을 막는 규칙이고, 실 LLM 프리뷰에서 실제로 관측돼 넣은 것입니다. 앵커를 허용하려면 그 규칙을 열어야 하는데, 방금 안정화한 게이트 축을 다시 흔드는 변경입니다.
2. 앵커를 쓰려면 프롬프트에 인용 규칙을 넣어야 하고 → `PROMPT_VERSION` 개정 → 24조합 골든이 함께 움직입니다.

**BE·FE가 알아야 할 것:** `cite_id`는 **목록 안의 순서 키**(L1·L2…)이고 본문과의 문장 단위 대응은 없습니다. 화면은 **각주 목록**으로 렌더하시면 됩니다. 필드 사전의 `cite_id` 설명("본문 앵커와의 연결 키")은 v1.1부터 유효합니다.

**대신 보장되는 것:** `citations`는 **항상 1건 이상**입니다(타입 차원 봉쇄 — 0건이면 `generated` 응답을 만들 수 없습니다). 인용 가능한 근거(`record_id`가 있는 fact)가 0건이면 **LLM을 부르기 전에** `rejected_insufficient`로 끊습니다.

## ② `label_suggestions[]` — v1에서는 **항상 빈 배열**입니다

생성기가 아직 없습니다(실측: `LABEL_SUGGESTION` 테이블·마이그레이션은 있고 생성 코드는 0건, `POST /v1/labels/suggest`도 문서만 있고 미구현).

**근거 없는 제안을 지어내지 않는다**(불변식 2)는 원칙상 빈 배열이 정직한 값입니다. 필드는 계약대로 존재하므로 BE 조립은 깨지지 않습니다.

🔴 **이걸 모르면 손해 보는 쪽이 BE입니다** — 라벨 검토함을 완성해 놓고 영원히 비어 있는 큐를 보며 자기 버그를 찾게 됩니다. **라벨 계약 §9의 "AI가 끝내야 할 것"은 현재 미충족 상태**입니다.

## ③ `draft_status` 와이어 4종 — **그대로 유지**(BE 영향 0)

`generated · rejected_insufficient · llm_failed · gate_exhausted` 계약대로 나갑니다.

내부 enum은 다릅니다(`generated · template_only · rejected_insufficient · failed`). 뒤의 둘은 판정이 아니라 **사유**라서 내부에서는 `failed`의 `status_reason`으로 살고, 라우터의 결정론 함수 한 곳이 와이어 4종으로 변환합니다. **BE가 받는 값은 계약 그대로**이니 화면 매핑표도 그대로입니다.

## ④ 4축 라벨 값 표기 정정 — **계약 예시가 틀렸습니다**

라벨 검토함 계약 §2 소유 표가 "4축 값 사전 → **AI 문서 정본**(ai docs 05 톤 매핑)"으로 이미 지정해 뒀습니다. 그런데 예시들이 enum과 다릅니다.

| 계약 예시 표기 | 정본 값 | 나온 곳 |
| --- | --- | --- |
| `anxiety_sensitive` | **`anxious`** | 인박스 계약 4곳(§3-①·§3-② 2곳·§4-①·§4-③) · 라벨 검토함 계약 1곳 |
| `data_pref` | **`data`** | 라벨 검토함 계약 2곳(`current_labels` · `PUT …/labels`) |

오타 하나가 아니라 **예시가 enum을 안 보고 쓰였다는 신호**라, 개별 수정이 아니라 두 계약 문서의 wire 값 예시를 **전수 대조**해 주시길 부탁드립니다. 위 표는 A가 grep으로 뽑은 결과입니다.

**alias는 받지 않습니다.** AI는 4축 enum 값만 수용하고 그 밖의 문자열은 **400**입니다. 와이어 alias는 BE가 한 번 보내기 시작하면 영구가 되고, 정본이 둘이 됩니다.

### ④-1. 부수 — FE 사전에 축별 전체 값 목록이 필요합니다

`interest`는 **3값**입니다: `grade` · `attitude` · **`admission`**. 조합 수 24 = 2×2×3×2가 그 실체입니다(로드 시 검증). 그런데 **계약 예시 어디에도 `admission`이 없습니다** — FE 사전에 축별 전체 목록을 넘기지 않으면 "입시 관심" 라벨이 렌더에서 누락됩니다.

| 축 | 전체 값 |
| --- | --- |
| `comm` | `data` · `narrative` |
| `sensitivity` | `anxious` · `direct` |
| `interest` | `grade` · `attitude` · **`admission`** |
| `frequency` | `frequent` · `monthly` |

## ⑤ `labels[]`는 **선택**입니다 — 누락 축은 기본값으로 채웁니다

라벨 검토함 계약 §6이 "라벨 0개 학부모 → 기본 톤으로 초안 생성됨을 안내(라벨은 선택)"를 확정했고, §0 원칙 ②("확정 전 미적용")에 따라 **개통 첫날은 전원이 라벨 0개**입니다. 4축을 필수로 요구하면 그날 초안이 한 건도 안 나옵니다.

- `ai docs 04` §4.2의 `label_snapshot` **필수 ✅ 표기는 ❌(선택)로 정정**했습니다.
- 누락 축의 기본값과 그 근거는 `part_a/05` **§7-2**가 정본입니다(`sensitivity=anxious` · `comm=narrative` · `interest=grade` · `frequency=monthly`).
- **안전 바닥은 라벨과 무관합니다** — A군 금칙어는 완충 0단계에도 들어 있어 라벨이 없어도 무조건 적용됩니다. 기본값이 정하는 건 완충의 **정도**지 유무가 아닙니다.
- **응답 `labels_applied`에는 요청분이 아니라 실제 적용된 4축 전부**를 싣습니다 — 화면이 "기본 톤으로 생성됨"을 알 수 있어야 §6 안내 문구가 나갑니다.
- 누락(축이 없음)은 정상이고, **미지값**(4축 enum 밖 문자열)은 400입니다. 둘은 다릅니다.
