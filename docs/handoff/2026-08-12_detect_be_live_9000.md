**AI 서버는 Windows에서 돌고 PostgreSQL은 WSL 안 도커에 있다.** 그래서 WSL VM이

**실측(2026-08-12):** 게이트 실행 중 두 번 발생했다.

```
PG 로그   : received fast shutdown request → database system is shut down
컨테이너  : ExitCode=0 · RestartCount=0     ← 크래시가 아니라 정상 종료
wsl uptime: up 1 min                        ← VM이 재부팅됐다
```

그 결과 ① 게이트 32건이 **"실 PG 미가용" skip**으로 초록처럼 보였고 ② 붙어 있던

**대응:** `.wslconfig`를 고치면 `wsl --shutdown`이 필요해 **다른 프로젝트 컨테이너까지**
내려가므로, **WSL 세션 하나를 붙잡아 두는 방식**으로 막았다(되돌리려면 그 세션만 끝낸다).
로컬 `docker-compose.yml`에는 `restart: unless-stopped`를 넣었다.

> 🔴 **BE 실통신 중에는 그 유지 세션을 끊지 말 것.** 끊기면 정상 요청이 500으로 바뀐다.

> 서버가 Alembic이 아니라 `create_all` 스키마 위에서 돈다(실측: 테이블 43개는 남고
> 원장만 사라짐). 그래서 **게이트 완료 후** DB를 재생성하고 정본 스키마를 다시 적용한 뒤
> 서버를 기동했다. — 장기적으로는 **테스트 격리 결함**이다(별건).

```
① 게이트 완전 종료
② checkon_ai DB만 DROP → CREATE      (다른 프로젝트 PG는 미접촉)
③ alembic upgrade head               exit 0 · 0001→0010 순차 적용
④ alembic_version = 0010_counsel_ctx_draft_body
⑤ 애플리케이션 테이블 40개 · ai_run·signal·feature_week 존재
⑥ python -m ai.agents.checkpointer   exit 0
⑦ 같은 명령 재실행                    exit 0  (멱등)
```

체크포인터는 두 번 모두 `체크포인터 스키마 준비 완료(재실행 가능)`만 출력했고
**접속정보는 한 줄도 나오지 않았다.** `checkpoints`·`checkpoint_blobs`·
`checkpoint_writes`·`checkpoint_migrations` 생성 확인.


### 🔴 BE 재시도 규칙

- **400·409는 재시도 대상이 아니다.** 400은 DTO·데이터 생성 문제, 409는 운영 확인 대상
  (로그·DLQ)이다. **5xx처럼 다루면 안 된다.**
- 재시도는 **연결 실패·timeout·503·504**만. 그때도 **같은 `Idempotency-Key`·같은 body·
  같은 hash**를 유지하고 횟수 상한을 둔다.
- **read timeout은 60초 이상**으로 둔다.
- 🔴 **응답 JSON 키 순서를 비교하지 말 것** — 아래 별건 B. Java에서는 **DTO 또는 구조 값**으로 비교한다.

## 7. 남은 BE 작업

1. BE 호스트에서 `curl -i http://<AI-HOST>:9000/openapi.json` → 200 (**네트워크·프로세스 확인용**이지 DB readiness 판정이 아니다)
2. Kafka Consumer가 받은 이벤트를 정본 요청 JSON으로 변환 → `POST /v1/detect`
   - `Idempotency-Key`는 **같은 Kafka 이벤트면 같은 값**, `X-Request-Id`는 **HTTP 시도마다 새 값**
3. Java DTO 역직렬화 — `data.signals` 7건 · `data.stats` · `meta.versions` · enum·날짜·nullable
4. 같은 이벤트 재전달 → 200 · **구조 값**으로 비교(바이트 비교 금지)
5. 같은 키 + 다른 body/hash → 409를 재시도하지 않고 운영 확인으로 분류
6. 잘못된 evidence → 400을 그대로 재시도하지 않기
7. Java canonical 전문·digest를 §6-B와 대조

연결 실패 시 확인 순서: uvicorn이 `0.0.0.0:9000`인지 · Windows 방화벽 TCP 9000 · 같은
네트워크인지 · AI 서버 IP가 그대로인지 · **WSL·PostgreSQL 유지 세션이 살아 있는지**.
⚠ **공용 인터넷에 9000을 무제한 노출하지 않는다.**

## 9. 확인 체크리스트 (BE용)

```
□ Base URL은 http://<AI-HOST>:9000 — Kafka가 아니라 HTTP로 직접 호출한다
□ read timeout >= 60초
□ Idempotency-Key = Kafka 이벤트 단위 · X-Request-Id = HTTP 시도 단위
□ 400·409를 재시도 가능한 5xx로 오판하지 않는다
□ 재요청 응답은 바이트가 아니라 DTO·구조 값으로 비교한다
□ DB ID(signal 행 id)로 조회하는 계약을 만들지 않는다
□ /openapi.json 200은 네트워크 확인이지 DB readiness가 아니다
□ 🔴 실통신 중 WSL 유지 세션을 끊지 않는다 — 끊기면 정상 요청이 500이 된다
```
