## 안건 ① R4 "숨은 위기" 강등 — ★핵심 → 동시 진단 보조 🔴

### 확정 문구 (이 표현 그대로 써 주세요)

> **성과 하락에 대한 선행성은 대규모 타 도메인 로그에서 근거를 찾지 못했다. 활동 종료와의 연관은 방향성이 있으나 검열 분리 불가로 확정할 수 없다. 조기 경보 주장은 자체 데이터 검증 전까지 보류하고, 동시 진단 보조로 재정의한다.**

**"반증"·"값어치 0"이라고 쓰지 않습니다.** 이유 둘 — ⓐ 파일럿에서 **우리 데이터로 재검증할 자리**를 남겨야 하고 ⓑ 리뷰어가 *"영어 앱 데이터인데요?"* 로 찌를 때 이 표현이 방어가 됩니다.

### 왜 그래도 강등인가

1차 검증이 **이탈 검열**에 걸려 있었습니다 — 필터가 생존을 세 번 걸러(`MIN_SOLVES=200`·`MIN_WEEKS=8`·"이후 2주 이상 관측") **무너진 학생은 표본에서 아예 빠졌습니다.** 검열을 보정해 다시 봐도(3,968주 복원) 정확한 R4 조건(정답률 유지 + 시간 1.5배↑)에서는 **n=88, 신뢰구간 중첩 — 확정 불가**입니다.

**"★제품 핵심 차별점"이라는 주장의 근거가 문서 서술뿐이었다는 사실은 검열 보정 후에도 변하지 않습니다.** 근거 없이 핵심이라 부르던 것을 내리는 게 정직한 처리라고 봅니다.

### 파급 — 이게 합의가 필요한 이유

| 대상 | 무엇이 바뀌나 |
| --- | --- |
| **기획서 §7.1 · 4.3** | "제품 핵심 차별점 ★핵심" 서술 |
| **`signal_type` 계약** | `hidden_risk` 값 자체는 유지, **지위·설명 문구**가 바뀝니다 |
| **신호 카드 화면** | ★ 강조·정렬 우선순위 |
| **발표덱** | 차별점 슬라이드 |

⚠ **값 삭제가 아닙니다** — `signal_type`에서 `hidden_risk`를 빼자는 제안이 아니라, "조기 경보"라는 **주장의 강도**를 내리자는 제안입니다. 계약 enum은 그대로입니다.

## 안건 ② R1 임계 — 고정 15%p → 잔차 분위 (2단 구조)

**측정된 것**

| 지표 | 값 |
| --- | --- |
| 개인 8주 기준선 대비 주간 정답률 변동 표준편차 | 12.5%p → **10.8%p**(난이도 보정 후, 14% 감소) |
| 현행 −15%p 임계 발동률 | 10.5% → **7.6%**(헛울림 **28% 감소**) |
| 잔차 하위 5% 분위(−18.5%p) 고정 적용 적중률 | **37.8%** |

**2단 구조가 필수입니다** — 개인 분위는 콜드 스타트가 더 나쁩니다(8주 데이터로 5% 분위를 추정하면 **표본 8개**).

| 구간 | 기준 |
| --- | --- |
| 재원 2주 ~ 약 10주 | 테넌트 전체 잔차 분포의 분위 ← **검증된 건 이쪽뿐** |
| 이후 | 개인 잔차 분포의 분위로 이행 |

🔴 **개인 분위는 미검증입니다.** 37.8%는 전체 풀 분위를 고정 임계로 쓴 결과이지 개인 분위가 아닙니다.

**왜 좋은가:** "알림 수가 설계값이 된다"는 성질이 `09` §1-8 경보 상한 철학(강사의 주의 예산 관리)과 정확히 맞습니다 — 임계가 분위면 그 예산이 **사전에 계산**됩니다.

## 안건 ③ 기대치 입력 층 — **남은 건 `FEATURE_WEEK` 스키마뿐입니다**

> **백엔드 선행 조건은 해소됐습니다.** 아래 "백엔드 회신 반영" 절을 보세요 — `05` 계약 확장 요구가 사라졌고 **백엔드 추가 작업이 0**입니다.

판정 입력을 실제값에서 **잔차(실제 − 기대)** 로 바꿉니다. **v1 기대치는 속성 단위**(`area_tag × rollup(type_tag)`) 실측 평균입니다 — **셀 축과 같은 축**이라 안건 ④의 롤업 결정과 한 몸입니다.

**콜드 스타트 폴백은 전체 평균입니다.** 강사 난이도 입력으로 하면 안 되는 이유가 같은 검증에서 나왔습니다 — 난이도 라벨이 **비단조**였습니다:

| 라벨 | 실측 정답률 |
| --- | --- |
| EASY | 55.5% |
| NORMAL | **34.6%** |
| HARD | **49.2%** |
| SUPER_HARD | 31.8% |

**NORMAL이 HARD보다 어렵습니다.** 강사 입력도 같은 종류의 주관 라벨이라 같은 문제를 재생산합니다. 전체 평균 폴백은 **보정 없음과 동치**라 회귀 위험이 0이라는 장점도 있습니다.

🔴 **효과 수치의 단서:** §안건 ②의 "헛울림 28% 감소"는 **문항 단위 기대치 기준 실측**입니다. **속성 단위의 효과는 미측정**이며, 이 수치를 속성 단위 설계의 근거로 인용하지 않습니다(재검증 경로는 아래 G).

## 안건 ④ 감지 출력 4단계 어휘 — **감지 층만 남았습니다**

### 회의에 남는 논점 하나

감지 출력을 "떴다/안 떴다" 2단계에서 4단계로 넓히는 것 자체는 그대로입니다 — **"판정할 수 없음"을 표현할 자리가 없다**는 문제이고, C-2(빈 주 미버킷 · 99 D ㉔)를 여기 흡수합니다(빈 주를 0으로 버킷하되 **"판단 보류"로 표기**하면 R2·R3 발화량 폭증 없이 사각지대가 닫힙니다 — 발화 대신 **표기**).

**남은 논점:** 감지 층 4단계 어휘가 **R2·R3와 어떻게 붙는지**입니다. 발화량·화면 문구·`signal_type` 표현이 함께 움직여서 이건 여전히 합동 회의 대상입니다.

⚠ **어휘 후보 "신호 있음"은 철회됐습니다** — 주간 감지 층의 "신호"와 충돌합니다. **감지 층의 이름은 회의에서 정합니다.**

## 협의 결과(확정) — 셀 층 · A↔B 2026-08-02

**1·2차 교환으로 닫혔습니다. 회의 시간을 쓰지 않습니다. B 구현 착수합니다.**

### A. 근거 분리 — A 오류 인정 (1차 교환)

"하위 25% 그룹당 **8문항**"은 **표본 미달 = 판단 보류(`unknown`)** 의 근거입니다. `part_b/04:80`이 이미 `n < cell_min_items`를 `unknown`("판정 유보, 약점 아님")으로 처리하고 있으므로, **이 수치만으로는 새 값이 필요하다는 논거가 되지 않습니다.**

**경계의 근거는 별개입니다** — "표본은 찼는데 판정이 애매한 구간이 실재한다". 두 근거를 섞어 쓴 초안을 정정했습니다(13 §5-2).

⇒ 4번째 값은 **어휘 추가가 아니라 `ok`를 쪼개는 임계 신설**이고, 따라서 `threshold_config` 시트·`config_version`의 대상이 됩니다.

### B. 진단 셀 축 — 롤업으로 4종 유지 (2차 교환)

`type_tag`는 **확장**하되(태깅·출제·문항 메타 정확도), **진단 셀 축은 상위 범주 롤업으로 현행 4종 유지**입니다. ⇒ **셀 수 불변 · R6 무변경 · 감지 쪽 코드 무변.**

근거(B 제시 · A 수용): 오태깅은 "**안다고 틀리게 말하는 것**"이라 조용히 틀린 `weak`을 만들고, `unknown`은 "**모른다고 말하는 것**"입니다. **전자가 나쁩니다**(fail-closed와 같은 결).

**A 확인 조건 3 — 3차 교환으로 최종 확정**

**①** 부모 범주는 **`contracts/taxonomy.py` 양자 승인 절차 경유**. B 초안에 **자식 목록 · 부모 · 부모 없는 태그의 명시 목록 · 경계 사례**를 담고 **태깅 골든셋과 함께** 올립니다.

**②** rollup 매핑의 버전은 **`config_version`이 아니라 `taxonomy_version`** 입니다. 매핑 **실물이 `taxonomy.py`에 있는데 버전만 config에 두면 정본이 둘**이 됩니다 — gateway A-11(판정 소스가 둘로 갈렸던 건)의 교훈입니다. `VersionSet.taxonomy_version`은 이미 재현 키이고(`contracts/execution.py:66`), **`09` §2-13의 "동시 개정 대상 5 — `taxonomy_version` 승격"** 과도 정합합니다.

> **두 버전 키를 헷갈리지 않습니다.** **경계 임계값**(D의 폭 7%p 고정값)은 `threshold_config` 시트에 살아 **`config_version`**, **rollup 매핑**은 `taxonomy.py`에 살아 **`taxonomy_version`** 입니다. **값이 사는 곳이 버전을 정합니다.**

**③** 부모 없는 태그는 **모수 *양쪽*(개인 baseline · 셀)에서 제외**합니다. `tag_confirmed=False`(미태깅) 경로와 동일 취급입니다.

> 🔴 **셀에서만 빼면 안 됩니다(준영님 지적 · 수용).** 분자에서만 빼고 분모(baseline)에 남기면 **baseline이 오염돼 전 셀 `delta`가 계통적으로 밀립니다.** 한쪽만 빼는 것이 안 빼는 것보다 나쁩니다.

**부작용은 의도된 공백으로 수용합니다** — 부모 없는 태그(예: 어휘 문항)는 v1에서 비가시가 됩니다. 관측은 **B의 runtime 메트릭 이벤트**로 붙이되, ⚠ **이벤트 스키마도 양자 승인**이라 **B 구현 PR에서 A가 승인**합니다.

**🔴 같은 원칙이 A의 기대치 층에도 대칭 적용됩니다** — 부모 없는 태그 문항은 **기대 정답률 계산·잔차 모수 양쪽에서 제외**합니다. **B 진단만 빼고 A 잔차는 포함하는 비대칭은 금지**입니다(두 층이 같은 축을 쓰니 모수도 같아야 합니다).

### C. 셀 판정의 통계적 성격 — B 검산 수용

`cell_delta`는 **두 추정치의 차**라 SE가 합성됩니다(단일 비율 ±16%p보다 큼).

| 사실 | 값 |
| --- | --- |
| `weak` 컷 −15%p | **z ≈ 0.95** |
| 참 delta 0인 셀의 허위 `weak` 비율 | **약 17%** |
| 폭 7%p 경계 밴드가 1 SE가 되려면 | **n ≥ 51**(주 16문항·16셀 기준 **51주** — 도달 불가) |

⇒ **v1 셀 판정은 통계적 판정이 아니라 운영 힌트이며 자동 처방 근거가 아닙니다.** 이 문장을 `part_a/04`(R6 축 결정 절)와 `part_b/04` §4에 **쌍으로** 답니다. 자동 경로로 흐르는 유일한 값은 `overall_low`이고, **경계를 분모에 포함하는 것이 노이즈의 자동 처방 유입을 막는 방어**입니다.

## 백엔드 회신 반영(확정) — 문항 ID 불요 · 속성 단위 전환 · 2026-08-02

⇒ 종전 결론이었던 **"계약 확장 요청이 스키마 승인보다 선행"은 철회됩니다.** 확장을 요청하는 대신 **AI 쪽 설계를 바꿉니다.**

| 집계 축 | **셀 축과 동일**(안건 ④의 롤업 4종) — 두 설계가 같은 축을 씁니다 |
| 남는 승인 | `FEATURE_WEEK` 스키마(**양자**)뿐 |

**부모 없는 태그 문항은 기대·잔차 모수 양쪽에서 제외합니다**(위 B ③과 대칭 — 같은 축이니 모수도 같아야 합니다).

**국어 도메인 근거 — 속성 단위가 오히려 강건합니다.** 지문·풀이를 공유하는 구조라 **문항 응답이 서로 오염**되고(난이도 드리프트), **유사·변형 출제**가 많아 "같은 문항"의 경계 자체가 흐립니다. 문항 ID가 있었어도 그 ID가 가리키는 모집단이 시간에 따라 흔들립니다.

### ⚠ 열어 둔 것 — 효과는 미측정입니다

측정된 **"헛울림 28% 감소"는 문항 단위 기대치 기준**입니다. 속성 단위 효과는 아직 없습니다.

- **재검증 경로:** **EdNet CSV 재분석**(태그 묶음별 기대치 재계산) — 파일럿 전에도 값을 얻을 수 있습니다(13 §8 ⑤).
- **재논의 조건:** 파일럿에서 **속성 단위 보정 효과가 미달로 실측되면** 문항 단위·유사변형 묶음 ID를 다시 올립니다.
