제안 경로는 승인된 구현이 아니다. BE가 AI 응답과 학생·학부모·발송 정보를 합치는 facade 후보이며, 실제 경로 확정 전까지 FR(FE)가 하드코딩하면 안 된다.

4. 발송 흐름과 불변식

AI는 학부모용 내용을 제공하고, BE가 승인·PDF·수신자·대기열을 소유하며, FR(FE)는 상태를 숨기지 않는다.

FR(FE)

1. 목록·미리보기

BE facade 조회 → 준비 조건 표시 → 강사가 PDF 8쪽 확인 → report_id 선택

→
BE

2. 원자적 재검증

tenant·권한·recipient·ready·PDF hash·중복 키를 서버에서 다시 확인

→
BE

3. 대기열·결과

delivery job 생성 → report 잠금 → 각 ID별 queued/rejected 반환 → 앱 노출

발송 가능 조건

✓ai_status == ready
✓audience == guardian
✓recipient_status == connected
✓pdf_status == ready

중복·동시성

✓Idempotency-Key 필수
✓같은 키·같은 body는 같은 결과
✓수정 리비전이 바뀌면 발송 거부
✓부분 실패를 200으로 뭉개지 않음

발송 후

✓리포트 읽기 전용
✓actor·시간·채널·PDF hash 감사
✓학부모 앱 목록에 발행일·쪽수 제공
✓재발송은 별도 delivery 기록
게이트와 리비전 불변식. AI 원문은 ReportBlockRevision.gate_passed의 기본값이 false인 실패 닫힘 상태에서 시작하며, ReportArtifact.validate_blocks는 게이트를 통과하지 않은 AI 블록의 산출 저장을 거부한다. 강사 수정본(ReportRevisionKind.TEACHER_EDIT)은 AI 산출물이 아니므로 이 게이트 대상이 아니다. 수정 시에도 ai_original은 지워지지 않고 리비전으로 남으며, restoreReportBlock 경로로 원문에 복귀한다. 정본은 src/ai/contracts/report.py의 ReportBlockRevision·ReportRevisionKind·ReportArtifact.validate_blocks이고, HTTP 보존 검사는 tests/ai/integration/test_report_router.py가 고정한다.

5. 상태·오류·캐시

AI 산출 상태와 BE 발송 상태는 다른 축이다. 한 개의 status enum으로 합치지 않는다.

상태 매트릭스

축값FR(FE) 표현
AIready검토·발송 후보
AIgate_rejected발송 불가, 수정·재검토
BEnot_sent미발송
BEqueued발송 처리 중
BEdelivered발송 완료·읽기 전용
BEfailed실패 이유·재시도 가능 여부

HTTP 처리

응답구분·FR(FE) 처리
400AI 현행. 요청 오류를 필터·수정 영역 가까이에 표시
404AI 현행. 목록에서 제거 후 “이미 삭제됨” 안내
409 REVISION_CONFLICTAI 현행. 강제 덮어쓰기 금지, 최신 상세 재조회
401 / 403 · 422 · 429 / 503BE facade 제안·미확인. 승인된 BE 계약이 생기기 전에는 응답 코드를 확정값으로 구현하지 않는다.
부분 실패BE 발송 제안·미확인. 성공 행은 잠그고 실패 행만 선택 유지
캐시. 목록 query key에는 tenant·월·반·상태·종류·검색·정렬·페이지를 포함한다. 블록 수정 성공 시 상세과 해당 목록 행을 함께 갱신하고, 409에서는 optimistic state를 버린 뒤 서버 상태를 다시 받는다.

6. 소유와 금지선

주체소유하지 않는 것
FR(FE)필터·검색·페이지·로딩/빈/오류·미리보기·2단계 확인·캐시발송 가능 여부를 화면 값만 보고 최종 확정하지 않음
AItenant 격리 조회·guardian audience·결정론 데이터·블록 리비전·409수신자·승인·PDF 저장·발송·앱 노출을 소유하지 않음
BE교사 권한·학생/학부모 매핑·목록 facade·PDF artifact·HITL·발송·감사·잠금AI의 gate 상태나 evidence 의미를 임의 재정의하지 않음
audience 경계 불변식. 반 평균·석차 같은 teacher_only 강사 화면 전용 지표는 학부모 리포트의 조립 단계에서부터 들어가지 않는다. 차단 지점은 src/ai/report/assembler.py의 filter_report_metrics(..., audience=...)이며, assemble_report_studio_data(*, audience)는 audience를 키워드로 반드시 받는다. 이 audience 필터를 프롬프트 지시로 대신하는 방식은 금지한다. 단, 필터가 적용되는 축은 ReportMetricInput.audience가 붙은 metrics뿐이고, ReportDataBlockKind의 여섯 데이터 블록은 이 필터를 타지 않는다. BE facade도 audience를 전달받아 같은 규율을 지키며 AI 응답을 되전달할 때 teacher_only를 통과시키지 않는다. 정본은 src/ai/contracts/report.py의 ReportAudience·ReportMetricInput.audience와 위 조립기 심볼이다.
추가로 유지하는 서비스 규율. 화면 수치는 결정론 코드와 evidence가 확정하며 LLM은 수치·판정을 만들지 않는다. 게이트 거부인 gate_rejected도 리포트 상세에서는 HTTP 200 상태로 돌려주고, AI에는 발송 경로가 없다. 정본은 CLAUDE.md 불변식 1·4, src/ai/api/routers/report.py, tests/ai/integration/test_report_router.py다.

7. 구현 완료 기준

FR(FE)

✓검색·필터·정렬·페이지가 URL과 동기화된다.
✓loading·empty·error·partial failure가 각각 보인다.
✓불가 행은 이유와 함께 비활성화된다.
✓7쪽 하드코딩을 제거하고 pageCount를 사용한다.

AI·BE 통합

✓X-Tenant-Id·X-Request-Id가 끝까지 전달된다.
✓409 충돌에서 원문과 최신 리비전이 보존된다.
✓발송 API는 idempotency와 부분 결과를 제공한다.
✓발송 완료 PDF hash와 학부모 앱 artifact가 같다.
결정 필요. BE facade 경로·operationId·delivery enum·수신자 연결 계약·PDF artifact 저장 위치는 아직 저장소에 확정 계약이 없다. 이 다섯 가지를 승인하기 전에는 FR(FE)가 제안값을 상수로 굳히지 않는다.
